# 1. Descobrir IP através de registros DNS

Pelos registros [[5. DNS (Protocol)|DNS]] de um domínio, é possível adquirir informações como endereço IPv4, IPv6, Mail Exchanger etc; informações que podem ser utilizadas para enumerar endereços IP de um alvo.

## 1.1. `dnsdumpster.com`

É um site que automatiza o processo de enumeração de IPs e identificação de subdomínios: [DNS Dumpster](http://dnsdumpster.com).

## 1.2. `host`

A ferramenta [[1. host]] é muito interessante para resolução de registros **A** e **AAAA**:

```shell
$ host itau.com.br
itau.com.br has address 23.73.216.40
itau.com.br has address 23.73.216.51
itau.com.br mail is handled by 1 post01.itau.com.br.
itau.com.br mail is handled by 1 post02.itau.com.br.
```

A partir disso, já temos um IP inicial com o qual podemos trabalhar e continuar a investigação. O 
`host` também pode traduzir subdomínios que **talvez** estejam sobre controle da empresa. Caso o IP inicial não tenha muitas informações, é possível tentar adquirir os IPs dos subdomínios e executar os processos novamente.

## 1.3. `dig`

Assim como o `host`, [[1. dig]] também pode ser usado para resolver registros DNS e descobrir IPs:

```shell
$ dig itau.com.br
```

## 1.4. Transferência de zona

Caso os [[5. DNS Name Server]] Autoritativos de um alvo estejam mal configurados, é possível realizar a operação de [[5. Transferência de Zona]], que consiste basicamente em adquirir todos os registros salvos no [[5. Zone File]] de um domínio em um **Name Server Autoritativo**. 

Um **Zone File** pode conter informações como registros **A**, **AAAA**, **CNAME** etc.

# 2. Descobrir bloco de rede ou ASN
## 2.1. WHOIS & RDAP

Com um [[5. IP (Address)|IP]] em mãos, podemos tentar descobrir qual o [[5. IANA#Net Number|net number]], ou seja, bloco de rede, que este IP faz parte. Isso pode ser feito com [[5. WHOIS (Protocol)|whois]] ou [[5. RDAP|rdap]].

```shell
$ whois <ip>
```

O `whois` pode trazer informações como `inetnum`, `NetRange`, `aut-num`([[5. Autonomous System#ASN|ASN]]) etc (lembre-se que whois não tem um padrão), contudo nem sempre isso pode estar relacionado diretamente com o alvo. Isso acontece, pois o IP pode estar sob domínio de um provedor ou empresa que os vende. Dito isto, eis os casos possíveis em uma enumeração com `whois`/`rdap`:

| Caso                            | Possível `inetnum`/`aut-num` | Implicação                           |
| ------------------------------- | ---------------------------- | ------------------------------------ |
| Site hospedado em VPS OVH       | OVH (não o dono do site)     | Você verá dados da OVH               |
| Empresa com ASN próprio         | ASN da empresa               | Alvo real, controle total            |
| Serviço hospedado em Cloudflare | ASN da Cloudflare            | Apenas borda da rede (não o real IP) |
| Proxy ou CDN                    | ASN do intermediário         | Pode ocultar o IP real               |
Podemos identificar o dono do IP através do `netname`.
