Para resolver o nome de um domínio, é necessário percorrer o seguinte trajeto **top-down**:

**Busca por registros do domínio `exemplo.com.br`**:
1. Pergunta aos [[#Root Server]]s informações sobre `exemplo.com.br`; os **Root Server**s respondem com os **[[#Autoritativo|Name Servers Autoritativos]]** da zona `.br`, ou seja os servidores `a.dns.br`, `b.dns.br` etc que são responsáveis pelo [[5. TLD]] `.br`.
2. Os **NS Autoritativos** para `.br` podem conter:
	- ou registros finais (**A**, **AAAA**, **CNAME** etc) para domínios de **subzonas não-delegadas**.
	- ou registros **NS** para **subzonas delegadas**, tipo `com.br`, `blog.br`, `edu.br` etc. Neste caso, ele não armazena os registros finais, apenas delega a responsabilidade para os **NS Autoritativos** da **subzona** específica.
   Como estamos buscando registros do domínio `exemplo.com.br`, então ele vai delegar para **NS Autoritativos** da subzona `com.br`[^2].
3. Os **NS Autoritativos** para `com.br` têm o mesmo comportamento dos **NS Autoritativos** de `.br`:
	- ou contém registros finais para domínios de **subzonas não-delegadas**.
	- ou contém registros **NS** para **subzonas delegadas**.
   Assumindo que `exemplo.com.br` é uma **subzona delegada**, isso significa que `com.br` não tem autoridade para manter registros finais desse domínio, portanto deve manter apenas os registros **NS**, permitindo a delegação para outros **NS Autoritativos**.
4. Por fim, o **NS Autoritativos** de `example.com.br` contém os registros finais (**A**, **AAAA**, **CNAME** etc) do domínio. Isso significa, por exemplo, que este **NS** mantém o mapeamento do domínio para seu respectivo [[5. IP (Address)]].

> [!NOTE] Subzonas Não-Delegadas
> Para fins de exemplo, caso exista a **subzona não-delegada** `dev.exemplo.com.br`, isso significa que sua zona pai (`exemplo.com.br`) pode conter seus registros finais, sem precisar delegar para outro **NS Autoritativo**.

---

[^1]: Uma **subzona** é uma divisão dentro de uma zona, ou seja, `dev.exemplo.com.br` é subzona de `exemplo.com.br`. Contudo, uma **subzona** pode ser ou **delegada** ou **não delegada**. **"Não delegada"** significa que seus registros finais são armazenados pelos **NS Autoritativos** da zona pai; desse modo, uma **subzona não-delegada** é apenas uma divisão "virtual" para representar hierarquia, e não autoridade. **"Delegada"**, por outro lado, significa que a **subzona** possui **NS Autoritativos** próprios, portanto a zona pai **não** pode manter registros finais dos domínios que pertençam à **zona delegada**, mas deve delegá-los para os **NS Autoritativos** corretos.

[^2]: No caso do Brasil, a zona `.br` e as subzonas `com.br`, `edu.br` etc compartilham os mesmos **NS Autoritativos**, ou seja, `a.dns.br`, `b.dns.br` etc, mas isso não é regra. Dessa forma, mesmo que `com.br` seja uma subzona delegada de `.br`, ambas compartilham os mesmos **NS Autoritativos**; a delegação existe apenas formalmente. Na maioria dos casos, zonas usam servidores diferentes para as **subzonas delegadas**, para fins de separação, loadbalancing etc.
