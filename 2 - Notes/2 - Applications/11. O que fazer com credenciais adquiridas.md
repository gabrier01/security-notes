Uma credencial adquirida é um **meio, não um fim**. O que fazer com ela depende de duas perguntas, nesta ordem:

1. **Que tipo de material é?** (senha em plaintext? hash? qual hash?) → decide *quais ações são possíveis*.
2. **Onde ela funciona?** (qual host, serviço, domínio?) → decide *o alcance* do acesso.

> [!summary] Fluxo geral
> **Triar** -> (Quebrar offline, Reutilizar online, Passar) -> Coletar mais -> Escalar -> *loop*.

# Triar a credencial

Antes de qualquer coisa, classifique o que você tem. Se for **hash**, identifique o formato com [[1. hashid]] (ou `john --list=formats`), porque o tipo determina o que dá pra fazer.

> [!warning] O gotcha central: **NT hash ≠ Net-NTLM**
> - **NT hash** (o hash do [[2. SAM]]/LSASS) *é* a chave de autenticação → pode ser **passado** (Pass-the-Hash) sem quebrar.
> - **Net-NTLMv1/v2** (o que o [[1. responder]] captura numa autenticação de rede) é um *desafio-resposta* → **NÃO** serve pra PtH; só dá pra **quebrar** offline ou **relayar**.
> Confundir os dois é o erro nº 1 nesta fase. Ver [[5. NTLM]].

## Tabela de decisão (tipo → ação)

| Tenho... | Quebrar? | Passar (PtH/PtT)? | Relay? | Vou para |
|---|:--:|:--:|:--:|---|
| Senha plaintext | — | — | — | [[#Reutilizar e validar (online)\|Reutilizar]] |
| NT hash | ✅ | ✅ | ❌ | Reutilizar/PtH **ou** Quebrar |
| Net-NTLMv2 (responder) | ✅ | ❌ | ✅ | Quebrar **ou** Relay |
| Kerberos TGT/TGS | ❌ | ✅ (PtT) | — | Reutilizar/PtT |
| Kerberoast / AS-REP | ✅ | ❌ | — | Quebrar |
| Hash Unix `$6$` (shadow) | ✅ | ❌ | ❌ | Quebrar |
| Chave SSH privada | — | ✅ (usar direto) | — | Reutilizar |

# Quebrar (offline)

Quando você não pode usar o material direto (ex: Net-NTLM, hash Unix, Kerberoast) **ou** quer a senha em claro (útil pra reúso e pra entender padrões de senha do alvo).

## 1. Identificar o formato

[[1. hashid]] sugere o tipo de hash.

## 2. Executar o cracker

[[11. john]] ou [[11. hashcat]] contra uma wordlist.

## 3. De onde vêm os hashes

| Fonte                 | Como se obtém                            | Nota                        |
| --------------------- | ---------------------------------------- | --------------------------- |
| SAM (Windows local)   | [[11. samdump2]] + [[2. SYSTEM]]         | NT/LM hash                  |
| Net-NTLMv1/v2         | [[1. responder]] (envenenamento de rede) | só crackável/relayável      |
| `/etc/shadow` (Linux) | leitura com acesso root                  | `$6$` sha512crypt etc.      |
| Kerberoast / AS-REP   | contas de serviço no AD                  | ver [[8. Active Directory]] |

# Reutilizar e validar (online)

A credencial é uma chave — a pergunta é **onde ela abre**. Aqui você não quebra nada: valida e usa.

## Descobrir o alcance (spraying)
[[11. nxc]] testa a credencial em massa contra SMB/WinRM/etc. e diz onde ela é válida e onde é **admin local**.

> [!caution] Cuidado com lockout
> *Password spraying* (uma senha × muitos usuários) evita bloqueio de conta; *brute force* (muitas senhas × um usuário) dispara lockout. Respeite a política do domínio e o escopo do engajamento.

## Pass-the-Hash (PtH)

Autenticar usando o **NT hash** sem conhecer a senha: [[11. wce]], [[11. mimikatz]] ou `nxc -H <hash>`.

## Pass-the-Ticket (PtT)

Reutilizar tickets **Kerberos** (TGT/TGS) obtidos da memória. Ver [[8. Active Directory]].

## Usar contra o serviço

Como usar a credencial validada num alvo depende do serviço (PsExec/SMB, WinRM, SSH, RDP, DB etc). Isso é o domínio dos playbooks **Atacando SMB / Atacando SSH** (a criar).

# Coletar mais credenciais

Com um acesso podemos tentar coletar mais credenciais.

## Windows local
- **SAM**: [[11. samdump2]] (offline, com [[2. SYSTEM]]) ou `reg save hklm\sam` / `reg save hklm\system`.
- **LSASS** (memória, sessões ativas): [[11. wce]] / [[11. mimikatz]].

## Domínio / Active Directory
- **NTDS.dit** ([[2. NTDS.dit]]): a base de todos os hashes do domínio.
- **DCSync**: pedir replicação a um DC pra extrair hashes sem tocar o disco. Ver [[8. Active Directory]].

## Linux / Unix
- `/etc/shadow` (hashes), `~/.ssh/` (chaves privadas), histórico de shell, arquivos de config com segredos.

---

# Escalar e persistir

A credencial nova destrava uma conta **mais privilegiada** (admin local → admin de domínio)? Se sim, volte ao **Triar** com o novo material — é aqui que o ciclo *triar → usar → coletar → escalar* de fato acontece.


---

# Registrar

Toda credencial validada entra no relatório final: qual conta, onde funciona, nível de privilégio e como foi obtida. Isso é o que sustenta o encadeamento de ataque na entrega.
