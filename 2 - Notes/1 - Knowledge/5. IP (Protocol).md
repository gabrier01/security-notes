**Internet Protocol** (IP) é um [[5. Protocolo]] usado para identificar cada dispositivo conectado numa rede para que as informações (pacotes) saiam de uma origem e cheguem no destino correto. Um pacote IP recebe o nome de datagrama.

# Cabeçalho

| Campo                      | Tamanho  | Descrição                                                    |
| -------------------------- | -------- | ------------------------------------------------------------ |
| **Version**                | 4 bits   | Versão do IP (4 para IPv4)                                   |
| **IHL (Header Length)**    | 4 bits   | Tamanho do cabeçalho (em palavras de 32 bits)                |
| **Type of Service (TOS)**  | 8 bits   | Prioridade e tipo de tráfego (agora chamado DSCP/ECN)        |
| **Total Length**           | 16 bits  | Tamanho total do pacote (cabeçalho + dados)                  |
| **Identification**         | 16 bits  | ID do pacote (usado na fragmentação)                         |
| **Flags**                  | 3 bits   | Controle de fragmentação (DF, MF)                            |
| **Fragment Offset**        | 13 bits  | Posição do fragmento (se fragmentado)                        |
| **Time to Live (TTL)**     | 8 bits   | Tempo de vida do pacote (quantidade de saltos permitidos)    |
| **Protocol**               | 8 bits   | Protocolo encapsulado (TCP=6, UDP=17, ICMP=1...)             |
| **Header Checksum**        | 16 bits  | Verificação de integridade do cabeçalho                      |
| **Source IP Address**      | 32 bits  | IP de origem                                                 |
| **Destination IP Address** | 32 bits  | IP de destino                                                |
| **Options (opcional)**     | variável | Usado raramente. Se presente, aumenta o tamanho do cabeçalho |
| **Padding (opcional)**     | variável | Zeros para alinhar o cabeçalho a múltiplos de 32 bits        |

> [!warning] Cabeçalho IPv4
> A tabela acima se refere apenas ao IPv4 e não ao IPv6. O IPv6 possui alguns campos diferentes e o tamanho dos campos `source ip address` e `dest ip address` são maiores.

# Fragmentação do pacote

O tamanho de um pacote do IP pode ser maior, por exemplo, do que o limite de tamanho de payload do [[5. Ethernet (Protocol)]] (1500 bytes). Neste caso, o pacote do IP deve ser **fragmentado** e para isso, existem três campos do cabeçalho que controlam a fragmentação: `identification`, `flags` e `fragment offset`.

## Identification

O campo `identification` é o que identifica o pacote, ou seja, fragmentos de um mesmo pacote vão possuir os mesmos bytes em `identification`.

## Flags

Através deste campo, constituído de apenas 3 **bits**, é possível identificar se um pacote IP é um fragmento ou não. Para isso, os últimos 2 bits que interessam:

- **2º bit** (`DF = Don't Fragment`): diz se um pacote é integral ou não, isto é, se seu valor for `1`, então significa que não é um fragmento, se for `0` então significa que é um fragmento.
- **3º bit** (`MF = More Fragments`): no caso de ser um fragmento, diz se há mais fragmentos, ou seja, se seu valor for `0`, então este é o último fragmento que constituí o pacote completo.

## Fragment offset

Este campo representa o offset em **qwords** (quad words = 8 bytes) em que inicia o payload do fragmento atual no pacote completo. Por representar **qwords**, o valor desse offset deve ser multiplicado por 8 para obter os **bytes**. Portanto, um pacote de offset 185 inicia no byte `185*8=1480`.

Através destes fragment offsets é possível organizar os fragmentos em ordem e constituir o datagrama completo. Além disso, quando o fragmento possuir a flag `DF=0 e MF=0` (indicando que é o último fragmento do datagrama), o sistema consegue calcular o tamanho do datagrama completo, ou seja, `(fragment offset * 8) + tamanho do payload do fragmento`.

# TTL

O **time to live** de um pacote é a quantidade de `hops` que aquele pacote pode fazer, isto é, a quantidade de vezes que o pacote pode passar por um dispositivo conectado à uma rede. Este contador é usado para evitar que o pacote trafegue infinitamente pela rede. Isso é especialmente útil para utilitários como o [[1. traceroute]].

Cada vez com o pacote faz um salto (hop) à uma dispositivo, seu `ttl` é decrementado em `1`. Assim que o `ttl` de um pacote chegue à `0`, então seu tempo de vida expirou e ele deve ser retornado ao [[5. Host]] de origem.


> [!Info] Sistemas Operacionais e `ttl`
> O `ttl` inicial pode indicar o sistema operacional de origem do pacote. Isso acontece, pois alguns sistemas atribuem um valor padrão específico. Exemplos:
> - `Linux: ttl 64`
> - `Windows: ttl 128`
> - `Unix: ttl 255`
>   
> Esses valores, contudo, podem ser alterados em registros e arquivos de configuração.
