O **Agendador de Tarefas (Task Scheduler)** é o componente do Windows que executa programas e scripts de forma automática, seja em horários definidos ou disparados por **eventos/gatilhos** (logon, inicialização, ociosidade etc.). Roda como o serviço `Schedule` e guarda as tarefas em `C:\Windows\System32\Tasks` e no registro.

Cada tarefa define uma **ação** (o que executar) e um **gatilho** (quando executar), e roda sob uma conta configurável, que pode ser `SYSTEM`.

# Gerenciamento local e remoto

- **Local**: `schtasks.exe`, o console `taskschd.msc`, ou os cmdlets PowerShell `Register-ScheduledTask`/`Get-ScheduledTask`.
- **Remoto**: via RPC (protocolo do Task Scheduler, sobre named pipes como `\pipe\atsvc`), trafegando pelo `IPC$` do [[5. SMB]]. O `schtasks /s [host]` opera dessa forma.

```shell
# Criar, executar e remover uma tarefa remota
schtasks /create /s [host] /tn [nome] /tr "cmd.exe /c [comando]" /sc once /st 00:00 /ru SYSTEM
schtasks /run    /s [host] /tn [nome]
schtasks /delete /s [host] /tn [nome] /f
```

# Relevância no pentest

É o motor de execução por trás do `atexec` (Impacket) e uma alternativa ao [[14. Service Control Manager|SCM]] para [[7. Remote Code Execution|execução remota]]. Como não cria serviço, **não gera o evento `7045`**, o que o torna mais furtivo (embora gere seus próprios eventos, como `4698 - A scheduled task was created`).

Também é uma técnica clássica de **persistência**: uma tarefa com gatilho de logon ou inicialização reexecuta o payload de tempos em tempos. Continua exigindo **credenciais de administrador local** no alvo.
