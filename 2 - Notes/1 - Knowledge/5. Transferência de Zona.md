Uma **Transferência de Zona** é uma operação legítima realizada através do protocolo [[5. DNS (Protocol)|DNS]] em que um [[5. DNS Name Server#Autoritativo|Name Server Autoritativo]] consulta outro **Name Server Autoritativo** para obter uma cópia atualizada de seus **RR (Resource Records)**. Em requisições **DNS**, o código dessa operação é `AXFR` é geralmente ocorre pela porta `53` sobre o protocolo [[5. TCP|TCP]].

> [!NOTE] TCP vs UDP
> Note que, diferente das outras operações DNS - como busca por registros **A**, **AAAA**, **CNAME** etc - uma operação **AXFR** ocorre na porta `53 TCP`.

Geralmente uma [[5. DNS Zone]] possui mais de um **Name Server** para fins de redundância, disponibilidade e load balancing. Para que esses servidores respondam de forma consistente, é necessário que estejam sincronizados e possuam os mesmo registros referentes aos domínios e subdomínios da zona. Para isso, um **Name Server Autoritativo** pode requisitar o `DNS Zone File` de outro **Name Server Autoritativo** para obter os registros mais atualizados da zona.

É possível realizar a transferência de zona com o seguinte comando [[1. dig]]:

```shell
$ dig AXFR <domain> @<name-server>
```

Ou com o comando [[1. host]]:

```host
$ host -l -a <domain> <name-server>
```

> [!redteam] Transferências de Zona ilegítimas
> É possível que algum **Name Server Autoritativo** esteja mal configurado e não restrinja quem pode realizar a **Transferência de Zona**. Neste caso, qualquer [[5. Host]] pode requisitar esta operação e obter todas os registros armazenados no **Zone File** do servidor para aquela zona, incluindo registros **A**, **AAAA**, **CNAME**, **MX** etc, expondo toda a estrutura da zona DNS.
