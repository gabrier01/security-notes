O arquivo `NTDS.dit` (NT Directory Services - Directory Information Tree) é o banco de dados principal do [[8. Active Directory]] em controladores de domínio (DC) [[Windows]]. Armazena todos os objetos do domínio, incluindo contas de usuários, hashes de senhas, grupos, computadores, políticas de grupo e outros atributos do diretório. O arquivo original fica em `%SystemRoot%\NTDS\ntds.dit`.


> [!NOTE] NTDS e Active Directory
> Enquanto o `NTDS.dit` é o banco de dados, o `NTDS` por si é o serviço que gerencia os recursos salvos neste banco de dados (cria, consulta, replica etc). A relação com o Active Directory é que este absorveu o NTDS e implementou outras funcionalidades (autenticação com Kerberos, resolução de DNS do domínio).

Assim como o [[2. SAM]], os hashes de senhas armazenados no `NTDS.dit` possuem uma camada adicional de criptografia, sendo necessário o arquivo [[2. SYSTEM]] para descriptografá-los e obter os hashes NTLM limpos.

> [!NOTE] Diferença em relação ao SAM
> Enquanto o [[2. SAM]] contém apenas contas locais da máquina, o `NTDS.dit` contém as credenciais de **todos os usuários do domínio**, tornando-o um alvo de alto valor em ataques de pós-exploração.

# Proteção

O Sistema Operacional obtém acesso exclusivo ao `NTDS.dit` durante a execução, bloqueando qualquer tentativa de leitura, escrita ou cópia direta. Qualquer tentativa de manipular o arquivo original alegará que ele está em uso por outro processo.

# Burlando bloqueio

Há algumas formas de burlar o bloqueio imposto pelo sistema, sendo elas:
- **Acessar o dispositivo fisicamente:** é possível fazer boot com Live CD, acessar o sistema de arquivos sem carregar o Windows e copiar o arquivo.
- **Montar uma cópia sombra ([[VSS]]):** tecnologia do Windows que permite criar snapshots consistentes de volumes em um ponto no tempo, possibilitando a cópia do arquivo mesmo enquanto está em uso por outros processos.
- **Usar o `ntdsutil`:** ferramenta nativa do Windows usada para manutenção do Active Directory. Permite criar um backup (`IFM - Install From Media`) que inclui uma cópia do `NTDS.dit` e do hive `SYSTEM`.
- **Extração remota com `impacket-secretsdump`:** com credenciais de administrador de domínio, é possível extrair os hashes diretamente pela rede sem precisar copiar o arquivo manualmente.

# Descriptografar campos protegidos

Com um arquivo [[2. SYSTEM]] em mãos é possível descriptografar localmente os hashes utilizando [[11. impacket-secretsdump]]:

```shell
$ impacket-secretsdump -ntds [ntds-file] -system [system-file] LOCAL
```

Para extração remota diretamente do controlador de domínio (DC):

```shell
$ impacket-secretsdump [domain]/[user]:[password]@[dc-ip]
```
