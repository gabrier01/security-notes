O **Domain Name System (DNS)** é um protocolo da [[5. Camada de Aplicação]] (porta `53`, [[5. UDP|UDP]]/[[5. TCP|TCP]]) responsável por traduzir **nomes de domínio** legíveis por humanos (ex: `example.com`) em endereços [[5. IP (Address)|IP]] utilizáveis por sistemas (ex: `93.184.216.34`), além de fornecer outras informações úteis sobre o domínio, chamadas de **Resource Records (RR)**

> [!info] TCP e UDP
> Geralmente `Queries` e `Responses` **DNS** operam sob o protocolo `UDP`. Contudo, a operação de [[5. Transferência de Zona]] é uma exceção e opera sob o protocolo `TCP`.

> [!info] Ferramentas
> Consultas DNS podem ser feitas utilizando as ferramentas [[1. dig]], [[1. host]], [[1. dnsrecon]] entre outras.

## 1. Cabeçalho

Estrutura do cabeçalho de um pacote **DNS**:

| Campo                                          | Tamanho (bits) | Descrição                                                                                                                                                                         |
| ---------------------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ID`                                           | 16             | Identificador único da requisição/resposta. Usado para parear query/response.                                                                                                     |
| [[#1.1. Destrinchando o campo `Flags`\|Flags]] | 16             | Conjunto de sub‑campos de controle (QR, Opcode, AA, TC, RD, RA, Z, AD, CD, RCODE) que definem se é query/response, tipo da operação, recursão, truncamento, códigos de erro, etc. |
| `QDCOUNT`                                      | 16             | Número de entradas na seção [[#2.1. Question\|Question]].                                                                                                                         |
| `ANCOUNT`                                      | 16             | Número de registros na seção **Answer**.                                                                                                                                          |
| `NSCOUNT`                                      | 16             | Número de registros na seção **Authority** ([[5. DNS Name Server#Autoritativo\|Name Servers Autoritativos]])                                                                      |
| `ARCOUNT`                                      | 16             | Número de registros na seção **Additional**.                                                                                                                                      |
O cabeçalho total é composto por `12 bytes` (`96 bits`) fixos.
### 1.1. Destrinchando o campo `Flags`

O campo `flags` do cabeçalho **DNS** possui `16 bits`, em que cada flag significa:

| **Flag**                                        | **bits** | **Descrição**                                                                           |
| ----------------------------------------------- | -------- | --------------------------------------------------------------------------------------- |
| `QR`                                            | 1        | Tipo da mensagem: `0=query`, `1=response`                                               |
| [[#1.2. Destrinchando a flag `Opcode`\|Opcode]] | 4        | Tipo de operação (`0=QUERY`, `1=IQUERY`, `2=STATUS`, etc).                              |
| `AA`                                            | 1        | _Authoritative Answer_. Indica se o servidor é autoritativo para a zona.                |
| `TC`                                            | 1        | _Truncated_. Se 1, a mensagem foi truncada (usualmente por limite do UDP).              |
| `RD`                                            | 1        | _Recursion Desired_. Cliente solicita resolução recursiva.                              |
| `RA`                                            | 1        | _Recursion Available_. O servidor suporta resolução recursiva.                          |
| `Z`                                             | 1        | Reservado (sempre `0`). Futuras extensões.                                              |
| `AD`                                            | 1        | Dados validados via DNSSEC (reservado em algumas implementações)                        |
| `CD`                                            | 1        | Cliente desabilita checagem DNSSEC (reservado em algumas implementações)                |
| `RCODE`                                         | 4        | Código de resposta (Mais comuns: `0=NoError`, `3=NXDOMAIN`, `2=SERVFAIL`, `5=REFUSED`). |

### 1.2. Destrinchando a flag `Opcode`

A flag `opcode` possui `4 bits`, podendo conter os seguintes valores :

| Valor (Bin/Dec) | Nome     | Descrição técnica                                                          |
| --------------- | -------- | -------------------------------------------------------------------------- |
| `0000` (0)      | `QUERY`  | Consulta padrão DNS (ex: **A**, **AAAA**, **MX**, etc). A mais comum.      |
| `0001` (1)      | `IQUERY` | Consulta reversa _inversa_ (obsoleto, substituído por `PTR`).              |
| `0010` (2)      | `STATUS` | Solicita o status de um servidor DNS. Pouco usado.                         |
| `1000` (4)      | `NOTIFY` | Indica mudanças na zona DNS para secundários (ex: bind envia para slaves). |
| `0101` (5)      | `UPDATE` | Atualização dinâmica de registros DNS. Usado com DNS dinâmico.             |

## 2. Payload DNS

A estrutura geral de um payload **DNS** é a mesma tanto para requisições do tipo `query` quanto para requisições do tipo `response`. Um payload **DNS** consiste em quatro seções, na seguinte ordem: 
- `Question`: presente em ambos os tipos
- `Answer`: presente apenas na resposta
- `Authority`: presente apenas na resposta
- `Additional`: opcional, depende da query e da resposta

Para determinar se as seções estão preenchidas, basta consultar os valores em `QDCOUNT`, `ANCOUNT`, `NSCOUNT` e `ARCOUNT`.

### 2.1. Question

A seção question define os "filtros" para fazer a busca pelo registro que deve ser retornado, isto é, o domínio, o tipo de registro e a classe de protocolo do registro. A seção é constituída pelos seguintes campos:

| Campo                                              | Tamanho (bits) | Descrição                                           |
| -------------------------------------------------- | -------------- | --------------------------------------------------- |
| `QNAME`                                            | variável       | Nome do domínio terminado com bytes `null` (`0x00`) |
| [[#2.1.1. Destrinchando o campo `QTYPE`\|QTYPE]]   | 16             | Tipo de registro desejado (A, MX, AAAA, etc)        |
| [[#2.1.2. Destrinchando o campo `QCLASS`\|QCLASS]] | 16             | Classe do protocolo, geralmente `IN` (Internet)     |

#### 2.1.1. Destrinchando o campo `QTYPE`

Os possíveis valores que o campo `QTYPE` da seção `Question` pode ter são os seguintes:

| Valor (Hex/Dec)  | Nome    | Descrição                                                                     |
| ---------------- | ------- | ----------------------------------------------------------------------------- |
| `0x0001` / `1`   | `A`     | Endereço IPv4                                                                 |
| `0x0002` / `2`   | `NS`    | Name Server autoritativo                                                      |
| `0x0005` / `5`   | `CNAME` | Canonical Name (alias)                                                        |
| `0x0006` / `6`   | `SOA`   | Start of Authority (início da zona)                                           |
| `0x000B` / `12`  | `PTR`   | Pointer - resolução reversa (IP → nome)                                       |
| `0x000C` / `13`  | `HINFO` | Host Information. Sistema operacional, <br>arquitetura etc (raramente usado). |
| `0x000f` / `15`  | `MX`    | Mail Exchange                                                                 |
| `0x001c` / `28`  | `AAAA`  | Endereço IPv6                                                                 |
| `0x0010` / `16`  | `TXT`   | Texto arbitrário                                                              |
| `0x0011` / `17`  | `RP`    | Responsible Person                                                            |
| `0x0021` / `33`  | `SRV`   | Serviço (usado por SIP, XMPP etc)                                             |
| `0x0029` / `41`  | `OPT`   | Extensões DNS (EDNS)                                                          |
| `0x00fb` / `251` | `IXFR`  | Incremental Zone Transfer                                                     |
| `0x00fc` / `252` | `AXFR`  | Full Zone Transfer                                                            |
| `0x00fd` / `253` | `MAILB` | Obsoleto (mailbox-related)                                                    |
| `0x00ff` / `255` | `ANY`   | Todos os tipos (não recomendado hoje)                                         |

Existem outros tipos de `QTYPE`, mas os acima são os mais comuns.

> [!blueteam] Configuração de `SPF` no registro `TXT`
> No campo `TXT` é uma boa prática inserir configurações de [[5. SPF]], que determina quais servidores *sender* podem enviar email com aquele domínio. Se essa configuração estiver mal feita ou ausente, o domínio está suscetível à uma vulnerabilidade chamada [[4. Email Spoofing]]. 

#### 2.1.2. Destrinchando o campo `QCLASS`

Os possíveis valores que o campo `QCLASS` da seção `Question` pode ter são os seguintes:

| Valor (Hex/Dec)  | Nome  | Descrição                                   |
| ---------------- | ----- | ------------------------------------------- |
| `0x0001` / `1`   | `IN`  | Internet — **padrão absoluto**              |
| `0x0003` / `3`   | `CH`  | CHAOS — usado em consultas BIND version etc |
| `0x0004` / `4`   | `HS`  | Hesiod — sistema antigo do MIT              |
| `0x00ff` / `255` | `ANY` | Qualquer classe                             |

### 2.2. Resource Records: Answer, Authority e Additional

Cada entrada nessas três seções possuem a mesma estrutura, chamada formalmente de **Resource Records**. São nessas seções, especialmente a **Answer** que as informações úteis sobre o domínio são retornadas. A estrutura de cada resposta contida nessas seções é: 

| Campo      | Tamanho  | Descrição                                                                                                                                                                     |
| ---------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NAME`     | variável | Nome do domínio ao qual o registro pertence terminado em byte `null`(`0x00`) ou ponteiro para alguma região no pacote [^1]                                                    |
| `TYPE`     | 2 bytes  | Tipo do registro (ex: A=1, MX=15, CNAME=5, etc). Mesmo valores de [[#2.1.1. Destrinchando o campo `QTYPE`\|QTYPE]]                                                            |
| `CLASS`    | 2 bytes  | Classe (quase sempre `IN` = 1). Mesmos valores de [[#2.1.2. Destrinchando o campo `QCLASS`\|QCLASS]]                                                                          |
| `TTL`      | 4 bytes  | Time To Live — tempo em segundos para cache.                                                                                                                                  |
| `RDLENGTH` | 2 bytes  | Tamanho do campo `RDATA` em bytes.                                                                                                                                            |
| `RDATA`    | variável | Dados do recurso (ex: IP, nome canônico, prioridade, etc). Pode ter compressão com ponteiro. Para tipos `MX`, os dois primeiros `bytes` representam a prioridade do servidor. |
Lembre-se que cada uma dessas seções podem retornar mais de um resultado. **Answer** pode retornar múltiplos IPv4 para um mesmo domínio; **Authority** pode retornar mais de um **Name Server Autoritativo** etc.

---

[^1]: Caso seja um ponteiro, seu valor iniciará com o prefixo `0xCN` seguido por `2 bytes` que representar o `offset` do domínio dentro do pacote. Isso é amplamente utilizado para economizar espaço e o ponteiro pode apontar para a primeiro ocorrência do domínio no pacote, que geralmente se encontra na seção **Question**.
