**Hypertext Transfer Protocol** (HTTP) é um protocolo da [[5. Camada de Aplicação]] usado para requisitar e transferir dados na internet, comumente utilizado em aplicações web. Esses dados transferidos podem ser textos, imagens, vídeos, áudios etc.

A estrutura de um protocolo HTTP é composta pela `start line`, `headers` (opcional) e um `body` (opcional).

> [!info] Páginas HTML e APIs
> O protocolo HTTP é comumente associado à busca por páginas `HTML`, contudo seu uso se expande para APIs Web, por exemplo [[7. API REST|APIs REST]], que fazem uso idiomático do protocolo HTTP para realizar operações num `backend`.


# Tipos de payloads

O protocolo `HTTP` funciona com dois tipos de payload: `Request` e `Response`.
## HTTP Request

Tipo de pacote enviado por um `client http`, por exemplo um navegador, para requisitar um recurso no servidor web. Num payload padrão, a estrutura é a seguinte:

1. A `start line` identifica o método http, o path requisitado e a versão do protocolo.
2. (opcional) As próximas linhas caracterizam os campos de cabeçalho, no formato `<healder-name>: <header-value>`, exemplo `Content-length: 123`. Cada campo de cabeçalho é separado por uma quebra de linha `\r\n`. O último campo de cabeçalho é marcado por duas quebras de linha (`\r\n\r\n`).
3. (opcional) Após a dupla quebra de linha se inicia os corpo da requisição, contendo dados que serão enviados na request.

```http
POST /users HTTP/1.1
Host: api.example.com
User-Agent: PostmanRuntime/7.44.1
Content-type: application/json
Content-lengh: 58
Connection: keep-alive

{
    "username": "gabrier",
    "role": "pentester"
}
```

No exemplo acima, é feito uma requisição para o path `/users` usando o método `POST` indicando intenção de criar um usuário. O tipo do corpo é um `json` de `58B` contendo os valores especificados no body. Para que essa chamada seja aceita, o servidor HTTP deve possuir o path `/users` mapeado para o método `POST`.

> [!info] Requisição de página HTML
> Navegadores comumente fazem requisições `GET /some/path` para acessar o conteúdo de uma página. A resposta, geralmente, é um `HTML`. Isso pode ser identificado pelo cabeçalho `Content-type: text/html`.

> [!blueteam] Entender o `User-Agent`
> O `User-Agent` é um cabeçalho muito importante de entender, pois ele identifica o `client` utilizado para fazer a requisição, isto é, um navegador, uma ferramenta para realizar requisições http (postman, insomnia, curl), uma ferramenta de análise de vulnerabilidades (Nikto) etc. É possível estabelecer filtros com base no `User-Agent`, para evitar varreduras.

## HTTP Response

Tipo de pacote enviado por um `server http` e recebido por um `client http`. É a resposta para um `http request` respectivo. Segue a seguinte estrutura:

1. A `start line` contém a versão do protocolo e o `status code` indicando o resultado da operação. O `status code` é extremamente importante, pois indica o resultado da requisição. Para mais detalhes, ver [Status Code](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status).
2. (opcional) Assim como no `HTTP Request`, as próximas linhas caracterizam os campos de cabeçalho, seguindo o mesmo formato. Cada campo é separado por quebra de linha e o último campo é seguido por duas quebras de linha.
3. (opcional) Por fim, o corpo da resposta http, contendo os dados retornados pelo servidor ao cliente. Em situações em que não há corpo de resposta, é comum receber o status `204 No Content`.

```http
HTTP/1.1 201 Created
Powered-by: express
Content-type: application/json
Content-length: 153

{
    "id": "d1427c20-ca4a-4d7d-bfd2-9981d1775e48",
    "username": "gabrier",
    "role": "pentester",
    "createdAt": "2025-06-29T23:37:31Z"
}
```

No exemplo acima, a resposta indica que a requisição foi atendida com sucesso e o usuário foi criado (`201 Created`). Também contém o tipo de objeto retornado no body (`json`) e seu tamanho. Por fim, após as duas quebras de linha, se encontra o valor retornado.

> [!info] Resposta de página HTML
> Comumente servidores web retornam páginas HTML requisitadas por navegadores. O conteúdo dessas páginas, geralmente, são `HTML`. Isso pode ser identificado pelo cabeçalho `Content-type: text/html`.

# HTTP 1.0 Vs HTTP 1.1

Os principais pontos de diferença entre as versões `1.0` e `1.1` envolvem multi-hosting (um servidor, múltiplas aplicações), reuso de conexão TCP (keep-alive) e demais otimizações como cache, pipe-lining etc. 

| Aspecto                     | HTTP/1.0                                                                                            | HTTP/1.1                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **Conexões**                | Fecha a conexão por padrão. Em alguns casos o servidor suporta o cabeçalho `Connection: Keep-alive` | Mantém a conexão aberta por padrão (keep-alive)                   |
| **Host header**             | Opcional                                                                                            | Obrigatório (suporta múltiplas aplicações web num mesmo servidor) |
| **Pipeline de requisições** | Não possui                                                                                          | Suporta requisições em sequência sem esperar resposta             |
| **Caching**                 | Básico com cabeçalho `Expires`                                                                      | Avançado, suporta cabeçalhos `Cache-Control`, `ETag` etc          |
| **Erro detalhado**          | Limitado                                                                                            | Mais códigos de status e headers de erro                          |
| **Chunked transfer**        | Não suporta                                                                                         | Suporta (cabeçalho `Transfer-Encoding: chunked`)                  |
| **Bandwidth**               | Ineficiente                                                                                         | Mais eficiente, possui menos overhead                             |
