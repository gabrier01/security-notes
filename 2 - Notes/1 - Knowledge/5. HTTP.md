**Hypertext Transfer Protocol** (HTTP) é um protocolo da [[5. Camada de Aplicação]] usado para requisitar e transferir conteúdos web via internet. Esses conteúdos podem ser textos, imagens, vídeos, áudios etc.

A estrutura de um protocolo HTTP é composta pela `start line`, `headers` (opcional) e um `body` (opcional). Um pacote HTTP pode ser dividido em `HTTP Request` e `HTTP Response`

# HTTP Request

1. Num `HTTP Request` a `start line` identifica o método http, o path requisitado e a versão do protocolo.
2. (opcional) As próximas linhas caracterizam os campos de cabeçalho, no formato `<healder-name>: <header-value>`, exemplo `Content-length: 123`. Cada campo de cabeçalho é separado por uma quebra de linha `\r\n`. O último campo de cabeçalho é marcado por duas quebras de linha (`\r\n\r\n`).
3. (opcional) Após a dupla quebra de linha se inicia os corpo da requisição, contendo dados que serão enviados na request.

```http
POST /users HTTP/1.1
Host: api.example.com
User-Agent: PostmanRuntime/7.44.1
Content-type: application-json
Content-lengh: 58
Connection: keep-alive

{
    "username": "gabrier",
    "role": "pentester"
}
```

Exemplo de requisição HTTP para o path `/users` usando o método `POST` indicando intenção de criar um usuário. O tipo do corpo é um `json` de `58B` contendo os valores especificados no body. Para que essa chamada seja aceita, o servidor http deve possuir o path `/users` mapeado para o método `POST`.

O `User-Agent` é um cabeçalho muito importante de entender, pois ele identifica o `client` utilizado para fazer a requisição, isto é, um navegador, uma ferramenta para realizar requisições http (postman, insomnia, curl), uma ferramenta de análise de vulnerabilidades (Nikto) etc.
# HTTP Response

1. Num `HTTP Response` a `start line` contém a versão do protocolo e o `status code` indicando o resultado da operação.
2. (opcional) Assim como no `HTTP Request`, as próximas linhas caracterizam os campos de cabeçalho, seguindo o mesmo formato. Cada campo é separado por quebra de linha e o último campo é seguido por duas quebras de linha.
3. (opcional) Por fim, o corpo da resposta http, contendo os dados retornados pelo servidor ao cliente.

```http
HTTP/1.1 201 Created
Powered-by: express
Content-type: application-json
Content-length: 153

{
    "id": "d1427c20-ca4a-4d7d-bfd2-9981d1775e48",
    "username": "gabrier",
    "role": "pentester",
    "createdAt": "2025-06-29T23:37:31Z"
}
```

Exemplo de resposta retornada pelo servidor, indicando que a requisição foi atendida com sucesso e o usuário criado (`201 Created`). Também contém o tipo de objeto retornado no body (`json`) e seu tamanho. Por fim, após as duas quebras de linha, se encontro o valor retornado.
