Um **DNS Name Server** é um servidor que armazena **Resource Records (RRs)** de um domínio e responde consultas de busca por esses registros. Os **Resource Records** podem ser ou os registros finais (**A**, **AAAA**, **CNAME**, **MX**, **TXT**, **SOA** etc que associam nomes a dados específicos) ou registros de **NS (Name Server)**, usados para delegar a consulta do domínio para outros **Name Servers** que possuem autoridade sobre uma zona ou subzona.

**Name Servers** também são capazes de realizar uma operação chamada de [[5. Transferência de Zona]], útil para que múltiplos **Name Servers Autoritativos** de uma mesma zona estejam com os **RRs** sincronizados entre si.

## Tipos de Name Servers

Há diversos tipos de **Name Servers**, cada um servindo para um propósito específico.
### Autoritativo

Um **NS Autoritativo** é o servidor que armazena os registros de uma zona e fornece as respostas definitivas e mais atualizadas sobre os nomes (domínios) pertencentes a essa zona.

Para domínios dentro da zona, desde que não sejam **subzonas delegadas**[^1], o **Name Server Autoritativo** pode conter registros finais como **A**, **AAAA**, **CNAME**, **MX**, **SOA**, entre outros. Ou seja, os registros que mapeiam um nome a informações relevantes.

Para domínios que pertencem a **subzona delegas**, ou seja, quando a zona atual não tem autoridade sobre esses domínios, o **NS Autoritativo** mantém apenas registros **NS** que delegam a autoridade e encaminham a consulta para os **NS Autoritativos** da **subzona delegada**.

Por exemplo, um **Name Server Autoritativo** pode conter registros **A**, **AAAA**, **CNAME**, **TXT** etc para o domínio `exemplo.com.br`, mas conter apenas registros **NS** para a **subzona delegada** `sub.exemplo.com.br`.

> [!NOTE] Resumo
> Portanto, **Name Servers Autoritativos** são os servidores consultados para resolver a hierarquia DNS de um domínio, seja contendo os registros finais seja contendo o caminho para outros **Name Servers Autoritativos**.

### Cache

É um servidor `cache-only` que apenas armazena as respostas recebidas por servidor **upstream**. Isso significa que servidores do tipo **cache** não percorre a hierarquia DNS para achar os registros de um domínio. O máximo que ele faz é repassar a requisição para um servidor **upstream**, que são servidores [[#Recursivo (Resolver)|Recursivos]].

### Recursivo (Resolver)

É o tipo de **Name Server** usado frequentemente por usuários finais ou **Name Servers** do tipo **cache**. Ele percorre toda a [[5. DNS (Architecture & Hierarchy)|Hierarquia DNS]] para buscar pelos registros finais do domínio. Isso significa que, não tendo uma entrada no seu cache local para o domínio específico, ele realiza uma busca **top-down**, iniciando desde os [[#Root Server]]s até o servidor [[#Autoritativo]] que contenha as entradas dos registros DNS para o domínio.

Os servidores DNS da google (`8.8.8.8`) e cloudfare `1.1.1.1` são exemplos de **Name Servers Resolvers**.

[^1]: Uma **subzona** é uma divisão dentro de uma zona, ou seja, `dev.exemplo.com.br` é subzona de `exemplo.com.br`. Contudo, uma **subzona** pode ser ou **delegada** ou **não delegada**. **"Não delegada"** significa que seus registros finais são armazenados pelos **NS Autoritativos** da zona pai; desse modo, uma **subzona não-delegada** é apenas uma divisão "virtual" para representar hierarquia, e não autoridade. **"Delegada"**, por outro lado, significa que a **subzona** possui **NS Autoritativos** próprios, portanto a zona pai **não** pode manter registros finais dos domínios que pertençam à **zona delegada**, mas deve delegá-los para os **NS Autoritativos** corretos.
