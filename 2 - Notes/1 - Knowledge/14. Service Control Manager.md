O **Service Control Manager (SCM)** é o serviço do Windows responsável por gerenciar outros **serviços** do sistema, ou seja, criar, configurar, iniciar, parar e remover. Roda no processo `services.exe` e mantém o cadastro dos serviços no registro, em `HKLM\SYSTEM\CurrentControlSet\Services`.

Em Windows, um `service` é um programa que roda em segundo plano, geralmente sob uma conta privilegiada. Por padrão, muitos rodam como **`LocalSystem` (`NT AUTHORITY\SYSTEM`)**, a conta de maior privilégio local. 

# Acesso local e remoto

O SCM pode ser operado tanto localmente quanto de forma remota:

- **Local**: `sc.exe` (`sc create`, `sc start`...), `net start`/`net stop`, o console `services.msc`, ou os cmdlets PowerShell `Get-Service`/`New-Service`.
- **Remoto**: via RPC sobre a [[14. Named Pipe|named pipe]] `\pipe\svcctl`, que trafega pelo `IPC$` do [[5. SMB]]. É esse canal que as ferramentas de administração remota (e de ataque) utilizam.

# Relevância no pentest

Criar um serviço que aponta para um binário ou comando arbitrário e iniciá-lo resulta em [[7. Remote Code Execution|execução de código]], normalmente como SYSTEM. Isso exige privilégio de **administrador local** sobre o SCM do alvo.

> [!redteam] SCM para execução remota
> É esse o mecanismo por trás do PsExec e do `smbexec`: o binário é depositado via [[14. Compartilhamento Administrativo|ADMIN$]] e o SCM (via `\pipe\svcctl`) cria e inicia um serviço que o executa. O compartilhamento apenas escreve o arquivo; **quem executa é o SCM**.

> [!blueteam] Monitorar eventos de criação de serviço
> Quando um serviço é criado via SCM, é gerado o evento de ID `7045` (A service was installed). Esse evento pode ser monitorado para identificar criação de serviços maliciosos.

> [!redteam] Evitar eventos `7045`
> Como eventos `7045` são alvos fáceis de monitoramento, algumas vezes vale trocar o mecanismo responsável por executar o código malicioso. Para isso pode ser usado o [[14. Agendador de Tarefas]] e [[14. Win32_Process]].
