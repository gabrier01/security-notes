Cliente de linha de comando que faz parte do [[8. samba]] para interagir com serviços [[5. SMB]]. É capaz de enumerar, acessar e gerenciar recursos compartilhados por um host.

# Enumerar compartilhamentos

Enumera/lista quais recursos um host compartilha na rede:

```shell
$ smbclient -L \\[IP ou hostname] -U [username]
```

Por de baixo dos panos, o comando acima realiza, através do protocolo SMB, uma **Remote Procedure Call (RPC)** do tipo `NetShareEnumAll` para o host alvo, solicitando que ele enumere e retorne todos os recursos compartilhados. Nem todo `username` possui permissão para fazer esse tipo de RPC, portanto é possível que a requisição falhe.

# Acessar um compartilhamento

Se conecta a um recurso compartilhado pelo host, habilitando o modo interativo, em que é possível executar comandos, como listagem e download de arquivos (se for um diretório), envio de arquivos para impressora etc.

**Exemplo de pasta compartilhada:**
```shell
#            .- note que a barra mudou 
$ smbclient //[IP ou hostname]/[resource] -U [username]
smb: \> ls
smb: \> cd www/html
smb: \> more index.html # visualizar arquivo
smb: \> get index.html original-index.html # download
smb: \> put hacked-index.html # upload
smb: \> del index.html # delete
smb: \> rename hacked-index.html index.html # rename
```


**Exemplo de impressora compartilhada:**
```shell
$ smbclient //[IP ou hostname]/[resource] -U [username]
smb: \> print document.pdf
```

# Autenticação

As formas de autenticação abaixo são **ortogonais às operações**: qualquer uma delas pode ser combinada tanto com a enumeração (`-L`) quanto com o acesso a um compartilhamento.

## Credenciais e domínio

No SMB, a autenticação usa a credencial no formato `[domain]\[username]` + senha. O `-U` define o **usuário** e o `-W`/`--workgroup` define o **domínio** (workgroup):

```shell
$ smbclient -L \\[IP ou hostname] -U [username] -W [domain]
```

Se `-W` **não** for informado, o `smbclient` resolve o domínio nesta ordem de precedência:

1. `-W` na linha de comando
2. `workgroup = ...` na seção `[global]` do `/etc/samba/smb.conf`
3. Padrão compilado: `WORKGROUP`

O domínio também pode ser embutido direto no `-U`, dispensando o `-W`:

```shell
#                              .- domínio inline, equivale a -W [domain]
$ smbclient -L \\[IP ou hostname] -U [domain]/[username]
```

> [!tip] Quando o domínio importa
> - **Host standalone (conta local):** o servidor normalmente **ignora** o campo domínio e autentica o usuário localmente; pode omitir o `-W`.
> - **Host em [[8. Active Directory]] (conta de domínio):** o domínio precisa estar correto, senão a credencial é validada no lugar errado e a autenticação falha mesmo com usuário e senha certos.

## Null Session

Conexão anônima, sem senha (`-N`):

```shell
$ smbclient -L \\[IP ou hostname] -N
# -N: no password
```

## Guest

Conexão como usuário **convidado** (guest). A forma explícita é informar o usuário `guest` com senha vazia (o `%` separa `usuário%senha`):

```shell
$ smbclient -L \\[IP ou hostname] -U 'guest%'
```

Muitos servidores também mapeiam usuários inválidos/desconhecidos para a conta guest (configuração `map to guest = Bad User` no `smb.conf`). É por isso que uma tentativa com um usuário qualquer e sem senha as vezes acaba caindo como guest:

```shell
$ smbclient -L \\[IP ou hostname] -N -U [username]
```

> [!note] Guest × Null session
> - **Null session** (`-N`): conexão anônima, sem credencial.
> - **Guest** (`-U 'guest%'`): autentica na conta guest do servidor. Depende do servidor ter o guest habilitado.

# Servidores legados

Alguns servidores legados não sabem lidar com versões novas do protocolo SMB. Para isso, é necessário informar um parâmetro para o `smbclient` que o force a utilizar uma versão mais antiga:

```shell
$ smbclient -L \\[IP ou hostname] --option="client min protocol=NT1"
```

O exemplo acima, irá forçar o `smbclient` a usar a versão `SMB1` (também conhecida como `NT1`).
