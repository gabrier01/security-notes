Um **reverse shell**, assim como no [[7. Bind Shell]], permite a execução de comandos num host alvo de forma remota. Contudo, a diferença é que é o host atacante que abre uma porta e o host alvo que se conecta nessa porta.

O princípio é o mesmo: quando a conexão é estabelecida, todos os bytes enviados pelo host atacante são redirecionados para a entrada padrão do shell no host alvo, e os bytes de saída do shell retornam ao atacante.

# Vantagens

A vantagem de fazer um **reverse shell** é de conseguir burlar mecanismos de firewall, especialmente firewalls de rede que poderiam interceptar tentativas de conexão [[5. TCP]] do atacante. No caso do **reverse shell** é o alvo que tenta se conectar ao atacante.

# Possíveis problemas

Mesmo que que o **reverse shell** seja melhor alternativa ao **bind shell**, ainda é possível que o firewall do alvo bloqueie portas de saída. Contudo, o alvo precisa ter algumas portas de saída abertas para conseguir se conectar com a internet. É necessário descobrir que portas são essas que o host alvo pode se conectar e no host atacante configurar um listener nessas portas.

Por exemplo, digamos que o firewall do host alvo permita saída na porta `443`. O host atacante deve configurar o `ncat` em modo listening na porta `443` para fazer o **reverse shell**.
