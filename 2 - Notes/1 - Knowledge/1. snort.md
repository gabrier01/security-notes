Ferramenta de detecção e prevenção de intrusos ([[5. IPS|IPS]]/[[5. IDS|IDS]]). O `snort` é capaz de monitorar o tráfego de rede em tempo real e detectar atividades maliciosas com base em regras pré-estabelecidas ou configuráveis.  Se integrado com uma ferramenta de firewall (tipo [[1. iptables]]), `snort` pode funcionar como um IPS.

A partir do cabeçalho dos pacotes e conteúdo dos payloads, o `snort` é capaz de identificar:
- scan de portas
- ataques de buffer overflow
- scanning em aplicações web
- sql injection; etc

Exemplo de execução:

```shell
$ snort -c /etc/snort/snort.lua -i eth0 -A alert_fast -l /var/log/snort
# -c <config-file>: arquivo de configuração onde serão lido variáveis, regras etc
# -i <interface>: interface de rede que terão os pacotes analisados, poderia ser -i "interface1 interface2" para múltiplas interfaces
# -A <logging>: tipo de logging; "alert_fast" gera um "alert_fast.txt" que contém alguns detalhes dos pacotes que cairam em alguma regra. alert_full manda para o stdout
# -l <path>: caminho do log, "." por padrão.
```

> [!info] Modo silencioso
> A opção `-q` (quiet) ativa o modo silencioso do `snort`, em que nenhuma informação é exibida no terminal, a não ser pacotes capturados, se a saída for stdout.

> [!warning] Problemas ao analisar pacotes gerados pela mesma interface de rede
> O `snort` pode ter dificuldades para analisar pacotes gerados pela mesma máquina na interface de rede que está sendo monitorada. Isso ocorre porque, em muitos sistemas (como o Linux), o checksum de pacotes TCP/UDP gerados localmente só é calculado no momento do envio pela interface física. Quando o destino do pacote é a própria máquina, esse envio muitas vezes não acontece, e o pacote pode circular internamente com um **checksum ausente**. Como o `snort`, por padrão, verifica a integridade do checksum, ele considera esses pacotes inválidos e os descarta.
> 
> Para evitar isso, basta passar a opção `-k none`, que fará com que a ferramenta ignore qualquer validação de checkum.

# Conceitos

## Arquivo de configuração

Detalhes sobre arquivos de configuração do `snort` não serão discutidos. Contudo, é importante saber que este arquivo define quais regras serão executadas, formatos de log, variáveis, configuração de módulos, [[#Módulos DAQ (Data Acquisition)|daq]], interface de rede padrão etc. A linguagem de script para arquivos de configuração do `snort` é `lua` e tal arquivo pode ser informado via `-c /path/to/config.lua`. A ferramenta possui um arquivo padrão, localizado em `/etc/snort/snort.lua`, que geralmente é utilizado junto com a opção `-c`.

Se o arquivo for alterado, é possível validar suas configurações com:
```shell
$ snort -c /path/to/config.lua
```

## Módulos DAQ (Data Acquisition)

DAQ é uma camada de abstração responsável por capturar os pacotes da rede e direcioná-los ao `snort`. Por padrão, o DAQ utilizado é a `pcap`
### pcap

DAQ , baseado na `libpcap`, utilizado por padrão pelo `snort`. Faz **cópia** dos pacotes em kernel space para o userspace. Com o `pcap`, o `snort` analisa os pacotes em [[#Modo passivo|modo passivo]], funcionando apenas como IDS. Como é realizada uma cópia dos pacotes, é esperado que haja um overhead causado pelas camadas que o pacote passa antes de chegar ao `snort` bem como atrasos em momentos de pico de tráfego.

### AFPacket

DAQ utilizado quando é necessário que o `snort` funcione no [[#Modo inline|modo inline]], ou seja, atuando diretamente no tráfego de pacotes entre origem e destino, permitindo que ele inspecione os pacotes tempo real. Neste modo, todo o tráfego vai para uma região de memória compartilhada entre kernel e userspace, ou seja, o `snort` tem acesso aos pacotes originais ao invés de cópias .

Para especificar o DAQ AFPacket, basta usar a opção `--daq afpacket`.

## Regras

Uma regra é a **condição** sob a qual o `snort` realização uma **ação**. Uma regra tem o seguinte formato:

`[action] [protocol] [src_host] [src_port] -> [dst_host] [dst_port] ( [body] )`

Sendo que:
- `action`: qual ação será tomada
	- `alert`: faz log do pacote
	- `drop`: se `snort` executado em modo de [[#IPS]], rejeita silenciosamente o pacote
- `protocol`: tipo do pacote que deve ser analisado; `ip`, `icmp`, `tcp`, `udp` etc.
- `src_host`: endereço do host de origem; `any` para qualquer um
- `src_port`: porta do host de origem; `any` para qualquer uma
- `dst_host`: endereço do host de destino; geralmente é o [[5. IP (Address)|IP]] do dispositivo, mas pode ser `any`
- `dst_port`: porta do host de destino; `any` para qualquer uma
- `body`: parâmetros separados por `;` que refinam a regra; configura mensagem de log, metadados da regra, filtros genéricos ou específicos para o protocolo etc.
	- `msg`: mensagem que será exibida no log caso algum pacote seja capturado pela regra
	- `flags`: especifica as flags [[5. TCP|TCP]]. Ex `flags:S;`
	- `content`: busca pelo conteúdo no payload do pacote. Ex `content:"GET /admin";`
	- `sid`: signature id/identificador único da regra. Recomendável que inicie em `1000000` para evitar conflitar com regras oficiais. Ex `sid:1000001;`
	- `rev`: identificador da revisão; cada atualização na regra deve incrementar a revisão em `1`. Ex: `rev:1;`
	- `classtype`: tipo de classificação da regra. Deve ter um valor existente na seção **default classifications** no arquivo `/etc/snort/snort_defaults.lua`. Ex: `classtype: `

Mais detalhes sobre escrita de regras pode ser encontrado [aqui](https://docs.snort.org/rules/).

### Criar arquivo da regra

Um arquivo `.rules` é aquele que conterá regras que definem . Você pode criar todas as regras dentro de um único arquivo ou separar por escopo.

```shell
# custom_ssh.rules

# Monitora qualquer inicio de 3WHS para a porta 22
alert tcp any any -> 192.168.0.50 22 (
	msg: "Inicialização de conexão SSH";
	flags: S;
	sid: 1000001;
	rev: 1;
)
```

> [!warning] `sid` e `rev` são obrigatórios
> Toda regra criada **deve** conter um `sid` único e `rev`.

### Carregar regra

Com um arquivo de regras criado, há algumas formas de coloca-las em produção:

1. Carregar arquivo de regra com opção `-R`:
```shell
$ snort -c /etc/snort/snort.lua -R /path/to/custom.rules -i eth0 -A alert_fast
```

2. Especificar um diretório inteiro de regras com opção `--rule-path`:
```shell
$ snort -c /etc/snort/snort.lua --rules-path=/path/to/rules -i eth0 -A alert_fast
```

3. Editar o arquivo `/etc/snort/snort.lua` para incluir seu arquivo de regras dentro da variável `ips` (essa variável já existe, basta encontrá-la no arquivo):
```lua
ips =
{
	rules = [[
		include /path/to/custom.rules
	]]
}
```

```shell
$ snort -c /etc/snort/snort.lua -i eth0 -A cgm
```

# Modo passivo

O funcionamento padrão do `snort` é servir como um Intrusion Detection System ([[5. IDS]]). Neste modo, a ferramenta apenas monitora passivamente cópias dos pacotes recebidos pelo kernel, sem interferir no tráfego da rede. Desta forma, no modo passivo, a ferramenta é utilizada apenas para geração de alertas.

Ao configurar a regra abaixo:

```shell
alert http any any -> 192.168.0.19 80 (
	msg: "Tentativa de acesso a diretório restrito";
	http_method;
	content: "GET";
	http_uri;
	content: "/admin";
	classtype: web-application-attack;
	sid: 1000002;
	rev: 2;
)
```

O `snort` faria log de qualquer pacote do protocolo HTTP que tentasse acessar o path `/admin` de uma aplicação web.

## Regras padrão

Por padrão, o `snort` possui uma série de arquivos de regra no diretório `/etc/snort/rules`. É possível carregar essas regras seguindo umas das opção explicadas em [[#Carregar regra]].

> [!warning] `snort3` vs `snort2` 
> É possível que alguns arquivos de regra em `/etc/snort/rules` esteja na versão `2`. Dessa forma, se a versão utilizada for a `3`, será necessário fazer a conversão. Isso pode ser feito com o `snort2lua`. Antes, é recomendado  criar uma cópia da regra para um outro diretório tipo `rules-bkp`. Exemplo:
> ```shell
> $ cd /etc/snort
> $ mkdir rules-bkp
> $ cp /rules/icmp.rules rules-bkp
> $ snort2lua -c rules-bckp/icmp.rules icmp_v3.rules -o /dev/null
> ```
> *Este comando também faz com que o `snort` gere um `snort.lua`. Este arquivo pode ser ignorado, por isso seu output é direcionado para `/dev/null`*
