As permissões em sistemas baseados no [[Linux]] funcionam segundo o seguinte modelo:
- Permissões de **dono**
- Permissões de **grupo**
- **Outras** permissões

Cada **diretório** ou **arquivo** possui esses três conjuntos de permissões. 

# Diretório

As permissões de um diretório podem ser visualizadas com o comando [[1. ls]]: 

```shell
$ ls -d -l gabrier

[permissions]    [owner] [group]
drwx------    15 gabrier gabrier 4096 Jun 22 16:46 gabrier
```

A primeira parte da saída, como `drwx------`, representa o tipo de arquivo e as permissões de acesso no Linux.

**O primeiro caractere (`d`) indica o tipo de arquivo:**
- `d`: diretório     
- `-`: arquivo regular
- `l`: link simbólico
 **Os nove caracteres seguintes estão divididos em três blocos de três posições, representando as permissões de:**
1. owner
2. group
3. others
**Cada bloco pode conter:**
- `r` (read),
- `w` (write),
- `x` (execute),  
- ou `-` se a permissão estiver ausente.

Outras informações importantes nessa listagem é a exibição do **dono** e **grupo** do diretório: `gabrier` e `gabrier`, respectivamente.

# Arquivo

Assim como no caso de um diretório, as permissões podem ser visualizadas com `ls`:
```shell
$ ls -l secret.txt

[permissions]    [owner] [group]
-rw-rw-r--    1  gabrier example  20 Jun 22 18:28 secret.txt
```

Note que, diferente de um diretório, o primeiro caractere é `-`, significando que o item é um **arquivo**.

Além disso, cada um dos conjuntos de permissão **dono**, **grupo** e **others** possui valores: `rw-`, `rw-` e `r--`, respectivamente.

Note que neste caso, o **dono** do arquivo é `gabrier`, mas o **grupo** é `example`. Isso significa que não só o **dono** do arquivo pode acessá-lo (seguindo as permissões que o **dono** tem), mas também todos os usuários que fazem parte do grupo `example` (seguindo as permissões que o **grupo** tem).

# Exemplos

Assumindo que o usuário `username` exista e tenha as seguintes configurações no [[2. _etc_sudoers|/etc/sudoers]]:
```
username ALL=(username:example) ALL
```

Isso significa que `username` tem permissão para invocar binários utilizando apenas suas próprias permissões, contudo se passando como membro do grupo `example`. Dessa forma, mesmo que `username` não seja membro do grupo `example`, ele conseguirá acessar qualquer arquivo e diretório que seja acessível para membros do grupo `example`.
