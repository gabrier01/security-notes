Ferramenta de envenenamento de protocolos de resolução de nomes em redes locais Windows. Atua como um servidor falso que responde a requisições [[5. LLMNR]], [[5. NBT-NS]] e [[5. MDNS]], induzindo máquinas da rede a se autenticarem nela e capturando hashes **NTLMv1**/**NTLMv2**.

> [!redteam] Atacante precisa estar na rede dos alvos
> O atacante precisa estar conectado à mesma rede dos alvos para ser capaz de responder com pacotes falsos.

**Fluxo do ataque:**
1. Uma máquina tenta resolver um nome de host que não existe no DNS.
2. Como o DNS falhou, o SO transmite uma requisição LLMNR/NBT-NS em broadcast para a rede.
3. O `responder` responde a essa requisição se passando pelo host solicitado.
4. A máquina alvo tenta se autenticar via NTLM com o atacante.
5. O hash NTLMv1/NTLMv2 é capturado e pode ser quebrado offline.

# Uso

```shell
$ responder -I <interface> [opções]
# -I <interface>: interface de rede a ser usada (ex: eth0, tun0)
# -A:             modo de análise/passivo, captura sem envenenar
# -w:             ativa servidor WPAD (Web Proxy Auto-Discovery)
# -P:             força autenticação NTLM no proxy HTTP (usado com -w)
# -d:             ativa resposta para requisições DHCP
# -v:             modo verboso
```

Exemplo:
```shell
$ responder -I eth0
```

Os hashes capturados são salvos automaticamente em `/usr/share/responder/logs/`e podem ser identificados com [[1. hashid]] e quebrados com [[11. hashcat]] ou [[11. john]].

## Modo análise (passivo)

Escuta o tráfego sem enviar respostas falsas, usado para reconhecimento furtivo.

```shell
$ responder -I eth0 -A
```

## ProxyAuth (`-P`)

Usada em conjunto com `-w`, força autenticação NTLM no servidor WPAD que o responder sobe. Quando um cliente da rede busca o arquivo `wpad.dat` (configuração automática de proxy), o responder exige autenticação, capturando hashes **NTLMv2**.

```shell
$ responder -I eth0 -Pw
```

> [!info] Por que é muito usada?
> Diferente do envenenamento LLMNR/NBT-NS (que depende de falhas de resolução de nome), o WPAD é solicitado ativamente por navegadores e o Windows em redes sem proxy configurado. Isso aumenta significativamente a superfície de captura. Além disso, como força NTLMv2 (em vez de NTLMv1), os hashes capturados são mais difíceis de quebrar mas são válidos para [[4. Pass The Hash]].

## Arquivo de configuração

O arquivo de configuração pode ser encontrado em `/etc/responder/Responder.conf`. Alguns parâmetros interessantes para modificar:

- `RespondTo`: lista de IPs separados por vírgula que o responder irá enviar pacotes de resposta. Aceita range no formato `10.16.1.12-50`.
