Utilitário para quebrar hashes de senhas via brute force/dicionário. O John tenta descobrir a senha original a partir de um hash testando entradas de uma wordlist e comparando os hashes resultantes.

```shell
$ john <hash-file> --wordlist=<wordlist>
# --wordlist=<wordlist>: usa o arquivo como dicionário de senhas
# --format=<format>:     força o tipo de hash (ex NT, LM, phpass, etc)
# --fork=<n>:            paraleliza em <n> processos
```

Se `--format` não for informado, o `john` tenta detectar o formato automaticamente.

> [!tip] Diretório de wordlists e `rockyou.txt`
> O [[Kali]] já vem com wordlists pré-definidas em `/usr/share/wordlists/`. A wordlist `/usr/share/wordlists/rockyou.txt` é popularmente utilizada por conter cerca de 14 milhões de senhas em plain text adquiridas no vazamento RockYou de 2009.

> [!NOTE] Wordlist padrão
> O parâmetro `--wordlist` é opcional e pode ser omitido. Neste caso, o `john` usará a wordlist padrão `/usr/share/john/password.lst`.

# Exibir resultados

Após a execução, os resultados além de serem emitidos para a saída padrão, também ficam armazenados em `~/.john/john.pot` e podem ser reexibidos com:

```shell
$ john <hash-file> --show
```

# Formatos comuns

O `john` suporta uma série de formatos que podem ser informados explicitamente para guiar o programa. Todos os formatos suportados podem ser listados com:

```shell
$ john --list=formats
```

Alguns exemplos comuns:

| Formato       | Prefixo do hash | Descrição                                     |
| ------------- | --------------- | --------------------------------------------- |
| `NT`          | *(sem prefixo)* | Hashes NT do Windows (MD4)                    |
| `LM`          | *(sem prefixo)* | Hashes LM legados do Windows                  |
| `Raw-MD5`     | *(sem prefixo)* | Hashes MD5 "crus"                             |
| `md5crypt`    | `$1$`           | MD5 crypt (Linux antigo, Cisco IOS)           |
| `sha256crypt` | `$5$`           | SHA-256 crypt                                 |
| `sha512crypt` | `$6$`           | SHA-512 crypt (padrão atual do `/etc/shadow`) |
| `phpass`      | `$P$` ou `$H$`  | WordPress, phpBB                              |

# Regras de mutação

Além de testar a wordlist como ela é, o `john` pode **mutar** cada entrada aplicando regras de transformação (adicionar números no fim, deixar a primeira letra maiúscula, trocar letras por símbolos etc). Isso amplia bastante a cobertura a partir de uma lista base, sem precisar de uma [[7. Wordlist]] gigante.

```shell
$ john <hash-file> --wordlist=<wordlist> --rules # usa o conjunto de regras padrão ([List.Rules:Wordlist])
$ john <hash-file> --wordlist=<wordlist> --rules=<nome> # escolhe um conjunto
```

As regras ficam no `john.conf`, em seções `[List.Rules:<rule-name>]`, e [dá pra escrever as suas próprias](https://www.openwall.com/john/doc/RULES.shtml).

> [!tip] Gerar a wordlist mutada sem quebrar nada
> Com `--stdout` o `john` só imprime os candidatos gerados, útil para inspecionar as regras ou alimentar outra ferramenta (ex `hashcat`):
> ```shell
> $ john --wordlist=rockyou.txt --rules --stdout > rockyou_mutated.txt
> ```

# Casos de uso
## Quebrar hashes do `/etc/shadow`

É possível combinar os arquivos [[2. _etc_passwd|/etc/passwd]] e [[2. _etc_shadow|/etc/shadow]] com [[11. unshadow]] antes de passar para o `john`:

```shell
$ unshadow /etc/passwd /etc/shadow > unshadow.out
$ john unshadow.out --wordlist=/usr/share/wordlists/rockyou.txt

$ john unshadow.out --show
# some_user:foobar123:1001:1001:...
# admin:admin0129:1003:1003:...
```

> [!NOTE] `/etc/passwd` não é obrigatório
> Como o arquivo `/etc/passwd` contém informações sobre os usuários do sistema, ele não é necessário para quebrar as senhas em `/etc/shadow`. Seu uso é apenas para enriquecer o output da ferramenta.

> [!tip] Filtrar arquivos de hashes com [[1. grep]]
> Caso o arquivo de hashes seja muito grande, é possível filtrar com `grep` para buscar apenas as linhas desejadas, como por exemplo, filtrar por um username específico.

## Quebrar hashes NT/LM

Hashes obtidos via `hashdump` ([[11. meterpreter]]) ou [[11. fgdump]] seguem o formato abaixo e funcionam perfeitamente com o `john`:

```
<user>:<rid>:<lm-hash>:<nt-hash>:::
```

Quando o campo `<lm-hash>` contém o hash `aad3b435b51404eeaad3b435b51404ee` significa que o hash `LM` está desativado para este usuário, portanto ele utiliza hash `NT`. Isso pode ser especificado via `--format`:

```shell
$ john nt.hashes --format=NT --wordlist=/usr/share/wordlists/rockyou.txt
$ john lm.hashes --format=LM
```
