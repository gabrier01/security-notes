**Secure Shell (SSH)** é um protocolo de rede para acesso remoto a dispositivos numa rede. Diferente de outros protocolos para o mesmo propósito, como [[5. Telnet]], o SSH possui criptografia implícita, portanto a comunicação é segura desde os primeiros pacotes trocados no [[5. TCP#Three Way Handshake|Three Way Handshake]].

Serviços SSH, escutam, por padrão, na porta `tcp/22`, mas também é comum escutarem na `tcp/2222`.

> [!blueteam] Use SSH ao invés do Telnet
> Prefira o uso de SSH para serviços de conexão remota. Além de possuir criptografia implícita, também fornece modos de autenticação seguros e convenientes.

Geralmente, o cliente utilizado para interagir com serviços SSH é o [[1. ssh]].
# Métodos de autenticação

O protocolo especifica diversos métodos de autenticação além do convencional usuário e senha. Após o handshake ser feito e a conexão criptografada ser estabelecida, o cliente ssh requisita os tipos de métodos de autenticação disponíveis no servidor, enviando um pacote com a operação `SSH_MSG_USERAUTH_REQUEST`. O servidor então responde com os métodos disponíveis.

> [!info] Múltiplos métodos de autenticação
> Um servidor pode disponibilizar múltiplos métodos de autenticação pelo arquivo `/etc/ssh/sshd_config`. A ordem escolhida para as tentativas de conexão é uma configuração do lado do cliente, que pode ser encontrada em `~/.ssh/config` ou `/etc/ssh/ssh_config`.

## Senha

Método `password`, configurado por `PasswordAuthentication yes`. O cliente envia uma senha (já dentro do túnel criptografado) para o usuário correspondente.

O servidor então verifica a senha do usuário em [[2. _etc_shadow|/etc/shadow]].

```shell
$ ssh [username]@[IP]
# serviço responde com
[username]@[IP]'s password: 
```

## Chave pública

Método `publickey`, configurado por `PubkeyAuthentication yes`. O cliente se conecta com o usuário ao provar para o servidor  que possui uma chave privada correspondente a uma chave pública armazenada  em `/home/<username>/.ssh/authorized_keys`, sendo `<username>` o usuário utilizado no login.

É bem mais seguro que o método de senha, pois é resistente à brute force.

```shell
$ ssh [username]@[IP]
# ou
$ ssh [username]@[IP] -i /path/to/key
```

Se nenhum caminho para a chave for informado, o client `ssh` procura em `~/.ssh/`.

Para geração de chaves públicas e privadas, ver [[1. ssh-keygen]].

## Keyboard interactive

Método `keyboard-interactive`. Permite o servidor enviar diversos tipos de "desafios" para autenticar o cliente. O servidor pode simplesmente pedir a senha, mas também é capaz de pedir por token OTP, PIN, código enviado via email ou sms etc.

# Usuário `root`

Muitos servidores SSH desabilitam o login com usuário `root`. Isso é feito pela configuração `PermitRootLogin no` no arquivo `/etc/ssh/sshd_config`. É possível que esta configuração esteja como `prohibit-password`, permitindo login com o root via `publickey`. No pior cenário, do ponto de vista da segurança, a configuração estará como `yes`, permitindo qualquer tipo de meio de autenticação com o usuário root.

> [!blueteam] Proibir autenticação com `root`
> A melhor prática é sempre proibir autenticação com o usuário root ao configurar `PermitRootLogin no`. Se realmente houver necessidade de permitir o login, ao menos configure como `prohibit-password`, para que apenas usuários com chave pública devidamente configurada possam autenticar.
