**Secure Shell (SSH)** é um protocolo de rede que o acesso remoto a dispositivos numa rede. Diferente de outros protocolos para o mesmo propósito, como [[5. Telnet]], o SSH possui criptografia implícita, portanto a comunicação é segura desde os primeiros pacotes trocados no [[5. TCP#Three Way Handshake|Three Way Handshake]].

Serviços SSH, escutam, por padrão, na porta `TCP/22`, mas também é comum escutarem na `TCP/2222`.

> [!blueteam] Use SSH ao invés do Telnet
> Prefira o uso de SSH para serviços de conexão remota. Além de possuir criptografia implícita, também fornece modos de autenticação seguros e convenientes.

# Métodos de autenticação

O protocolo especifica diversos métodos de autenticação além do convencional usuário e senha. Após o handshake ser feito e a conexão criptografada ser estabelecida, o cliente ssh requisita os tipos de métodos de autenticação disponíveis no servidor, enviando um pacote com a operação `SSH_MSG_USERAUTH_REQUEST`. O servidor então responde com os métodos disponíveis.

> [!info] Múltiplos métodos de autenticação
> Um servidor pode disponibilizar múltiplos métodos de autenticação. A ordem escolhida para as tentativas de conexão é uma configuração do lado do cliente. Geralmente isso pode ser configurado em `~/.ssh/config` ou en `/etc/ssh/ssh_config`.

## Senha

Método `password`. O cliente envia uma senha (já dentro do túnel criptografado) para o usuário correspondente.

O servidor então verifica a senha do usuário em [[/etc/shadow]].

```shell
$ ssh [username]@[IP]
# serviço responde com
[username]@[IP]'s password: 
```

## Chave pública

Método `publickey`. O cliente se conecta ao provar que possui uma chave privada correspondente a uma chave pública armazenada no servidor em `~/.ssh/authorized_keys`.

É bem mais seguro que o método de senha, pois é resistente à brute force.

```shell
$ ssh [username]@[IP]
# ou
$ ssh [username]@[IP] -i /path/to/key
```

Se nenhum caminho explícito for informado, o client `ssh` procura em `~/.ssh/`

## Keyboard interactive

Método `keyboard-interactive`. Permite o servidor enviar diversos tipos de "desafios" para autenticar o cliente. O servidor pode simplesmente pedir a senha, mas também é capaz de pedir por token OTP, PIN, código enviado via email ou sms etc.
