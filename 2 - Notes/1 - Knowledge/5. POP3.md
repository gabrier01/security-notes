POP3 é a versão três do **Post Office Protocol**, protocolo da [[5. Camada de Aplicação]]. É utilizado para fazer download de mensagens de email de um servidor para um cliente de email local. Dependendo da configuração, as mensagens são removidas do servidor após o download, mantendo-as apenas localmente, portanto permitindo o acesso offline.

Servidores de email que permitem o download das mensagens via POP3 escutam, por padrão, na porta `tcp/110`. 


> [!warning] POP3 não oferece criptografia implícita
> O protocolo não possui nenhum tipo de criptografia built-in, portanto as mensagens são transferidas em texto legível. Qualquer interceptador será capaz de ler os emails. Existe o comando `STLS` (START TLS) para iniciar a comunicação criptografada, contudo isso fica a critério do cliente.

> [!blueteam] POP3S - POP3 criptografado
> Caso precise disponibilizar o download das mensagens de email, configure um serviço [[#POP3S]] ao invés de POP3. POP3S **obriga** que a conexão seja criptografada via [[5. TLS]] desde a etapa do [[5. TCP#Three Way Handshake|Three Way Handshake]].

# POP3S

Versão segura do POP3 que utiliza o protocolo [[5. TLS]] para criptografar a comunicação. A criptografia acontece desde os primeiros pacotes trocados, portanto não fica a critério do cliente enviar o comando `STLS`.

A porta padrão do POP3S é `TCP/995`.

# Conexão

Uma conexão com serviços POP3(S) pode ser estabelecida com utilitários como [[1. ncat|ncat]] e [[1. telnet|telnet]]. Para conexões criptografadas, pode-se utilizar o [[13. openssl#Client TCP criptografado|openssl]] ou `ncat` com a flag `--ssl`.

```shell
ncat -v [IP] 110
# ou
ncat -v --ssl [IP] 995
```

## Banner grabbing

Alguns serviços POP3 retornam uma mensagem após a conexão ser estabelecida, portanto, é possível fazer [[7. Banner Grabbing]]. 

> [!redteam] Identificar serviço e versão
> Banner grabbing é uma técnica trivial para identificação do serviço e versão. Essas informações são importantes para guiar os próximos passos de análise e exploração de vulnerabilidades, pois é possível que o serviço em questão seja vulnerável.

## Comandos

Após se conectar, o cliente pode enviar comandos em texto legível. 

- `CAPA`: 
- `STLS`: para serviços POP3, `STLS` inicia a comunicação criptografada. Nem todo serviço POP3 aceita TLS, seja por falta de implementação ou configuração.
- `USER [username]`: informa o usuário que irá fazer o login
- `PASS [password]`: informa a senha do usuário informado em `USER [username]`.
- `STAT`: exibe a quantidade de mensagens na caixa de entrada
- `LIST`: lista os índices e tamanho das mensagens na caixa de entrada.
- `UIDL`: similar ao `LIST`, contudo retorna o índice sequencial e o identificador único. Possui um parâmetro opcional `[index]` para retornar o ID único apenas de uma mensagem específica com base em seu índice.
- `RETR [index]`: retorna a mensagem com base no `índice` retornado em `LIST`.
- `DELE [index]`: marca uma mensagem para exclusão após logout
- `RSET`: cancela exclusões pendentes.
- `NOOP`: "no operation", não faz nada. A intenção é de manter a conexão ativa e evitar timeouts.
- `QUIT` encerra a conexão. Realiza qualquer deleção de mensagens pendente.


> [!blueteam] Monitorar `NOOP` consecutivos 
> `NOOP` consecutivos durante um longo período de tempo pode indicar a tentativa de um atacante manter uma conexão aberta indevidamente.
