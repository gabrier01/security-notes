Network Basic Input/Output System (NetBIOS) é uma [[7. API]] criada para permitir que dispositivos numa rede local possam se comunicar e compartilhar recursos. A API do NetBIOS fornece três funcionalidades: **registro e resolução de nomes**, **comunicação orientada a sessões** e **comunicação não orientada a sessões**.

> [!warning] NetBIOS **não** é um protocolo
> É importante deixar claro que NetBIOS **não** é um [[5. Protocolo|protocolo]], portanto, **não** define regras, ordem e significado dos dados para que uma comunicação aconteça. Todas as operações disponíveis pela interface NetBIOS são feitas sob os **NetBIOS Names**, que mapeiam um [[5. Host|host]] conectado na rede. A forma como a comunicação é feita é abstraída do usuário que utiliza a interface, contudo geralmente é utilizado o modelo TCP/IP.

> [!info] NetBIOS e SMB
> Devido as funcionalidades implementadas pelo sistema NetBIOS, ele foi muito utilizado na versão 1.0 do protocolo [[5. SMB]] para fazer compartilhamento de recursos na rede. Contudo sua aplicabilidade não se limita a isso.

# Funcionalidades

## Registro e Resolução de Nomes

O registro de nomes num sistema NetBIOS é essencial para a execução das demais operações. É responsável pela identificação de dispositivos em uma rede, permitindo que se comuniquem através de um nome simbólico, chamado de **NetBIOS Names**. A API define que estes nomes devem conter até `15 bytes (caracteres)` + `1 byte` de [[### NetBIOS Suffix|sufixo]], além de serem únicos.

Um nome registrado pode, posteriormente, ser **resolvido** para um identificador do dispositivo na rede, como o endereço [[5. IP (Address)|IP]]. Note que isso permite a comunicação com diversos hosts sem que o usuário saiba os IPs envolvidos.

> [!info] NetBIOS sem IP
> Historicamente, o NetBIOS foi projetado para operar sem depender do protocolo IP. Isso era viável porque o protocolo de transporte utilizado na época, o **NetBEUI**, funcionava exclusivamente em redes locais e não exigia endereçamento IP. A resolução de nomes NetBIOS ocorria por **broadcast**, de forma semelhante ao funcionamento do [[5. ARP (Protocol)|ARP]]: o host enviava um pacote de broadcast NetBEUI perguntando qual dispositivo possuía um determinado **nome NetBIOS**, e o host correspondente respondia informando seu [[5. MAC Address]].

### NetBIOS Suffix

Um **NetBIOS Suffix** é o 16º byte encontrado no **NetBIOS Name**. Esse sufixo é utilizado para identificar, e diferenciar, serviços em um mesmo host. Ou seja, um host, contendo um **NetBIOS Name**, pode fornecer diversos tipos de serviços sobre o sistema NetBIOS e esses serviços são diferenciados pelo sufixo. 

Os principais sufixos são:

| ------ | --------------------- | ------------------------------------------------------- |

| `<01>` | Grupo                 | Master Browser                                          |
| `<03>` | Individual            | Messenger Service (nome de usuário logado)              |
| `<06>` | Individual            | Remote Access Service (RAS)                             |
| `<1B>` | Individual            | Domain Master Browser (PDC)                             |
| `<1C>` | Grupo                 | Domain Controllers disponíveis no domínio               |
| `<1D>` | Grupo                 | Local Master Browser                                    |
| `<1E>` | Grupo                 | Browser Election Service                                |
| `<20>` | Individual            | File Server Service (SMB ativo)                         |
| `<21>` | Individual            | Remote Access Service (RAS) Client                      |
| `<22>` | Individual            | Microsoft Exchange Interchange                          |
| `<23>` | Individual            | Microsoft Exchange Store                                |
| `<24>` | Individual            | Microsoft Exchange Directory                            |
| `<2B>` | Individual            | Lotus Notes Server                                      |
| `<2F>` | Individual            | Microsoft SQL Server                                    |
| `<31>` | Individual            | MS-SNA Server                                           |
| `<43>` | Individual            | SMS Clients                                             |
| `<44>` | Individual            | SMS Administrador                                       |

## Comunicação orientada a sessões

Para que dois hosts conectados numa rede e identificados por seus **NetBIOS Name** se comuniquem com segurança, é necessário estabelecer uma sessão. A sessão permite um controle lógico de quem pode se comunicar com quem e quais as operações permitidas.

Cada sessão possui um **ID** e permite que um host se conecte, de forma individual, com múltiplos outros hosts, sem que uma conexão interfira na outra. A sessão também controla timeouts, confirmação de recebimento, quem pode enviar dados e quanto etc.

> [!warning] Sessão ≠ Criptografia
> A segurança estabelecida por uma sessão não é no sentido criptográfico, mas apenas de controle lógico, como dito anteriormente.

Atualmente as sessões são controladas via TCP/IP.

## Comunicação não orientada a sessões

Esse tipo de comunicação oferece operações mais simples, que não necessitam de um fluxo contínuo e ordenado de dados. Geralmente é utilizado para transmitir mensagens para múltiplos hosts conectados (útil para fazer anúncio), consulta de nomes etc.

Atualmente esse tipo de comunicação é empregada via UDP.

# NetBIOS sobre TCP/IP

Como dito, o NetBIOS é apenas uma interface que define operações para que dispositivos se conectem e se comuniquem numa rede. Ele não define nenhuma regra, ordem e significado dos dados para permitir a comunicação, portanto **não** é um [[5. Protocolo|protocolo]].

Contudo, existe o **NetBIOS over TCP/IP** ou **NetBT**, que é um protocolo construído sobre a pilha [[5. TCP|TCP]]/[[5. IP (Address)|IP]],  permitindo que aplicações que utilizem a API do NetBIOS possam funcionar em redes modernas, utilizando o IP e TCP para endereçamento e transporte de dados, respectivamente.

As três funcionalidades oferecidas pelo NetBIOS são servidas nas seguintes portas da camada de transporte:

| Porta                 | Funcionalidade                                                                       |
| --------------------- | ------------------------------------------------------------------------------------ |
| `137/udp` e `137/tcp` | Serviço para registro e resolução de nomes                                           |
| `139/tcp`             | Serviço para gerenciamento de sessão para comunicação orientada a sessões            |
| `138/udp`             | Serviço para distribuição de datragams para comunicação **não** orientada a sessões. |

> [!tip] Utilitário `nbtstat`
> Sistemas Windows geralmente possuem o utilitário [[1w. nbtstat]], usado para  diagnosticar e resolver problemas relacionados ao **NetBT**. Com ele, é possível identificar hosts  que potencialmente possuem algum recurso compartilhado na rede.

> [!tip] Utilitário `nbtscan`
> Sistemas Linux podem utilizar o utilitário [[1. nbtscan]] para varrer a rede e identificar hosts com o serviço **NetBT** ativo, potencialmente possuindo algum recurso compartilhado.
